# บ้านเรา — แผนที่มีชีวิต
## Game Design Document v2

**Working title:** บ้านเรา / Baanrao: Living Atlas  
**ชื่อโครงการเดิม:** Siam Street Pixel  
**วันที่:** 14 ตุลาคม 2569 (2026-10-14)  
**สถานะ:** Concept proposal สำหรับสร้างและทดสอบต้นแบบ — ยังไม่มีเกม และยังไม่ใช่ Approved for Production  
**แนวเกม:** เกมจำลองชีวิตและสร้างชุมชนร่วมกันบนแผนที่ประเทศไทย เล่นต่อกันได้โดยไม่ต้องออนไลน์พร้อมกัน  
**แพลตฟอร์มเริ่มต้นที่เสนอ:** Mobile-first Web / PWA พร้อม desktop  
**คำชวนเล่น:** “มีที่ของคุณ มีสิ่งที่คุณถนัด มีคนรอเห็นสิ่งที่คุณสร้าง”

เอกสารประกอบ: [งานวิจัยประเทศไทย](docs/thailand_research.md) · [ทิศทางเทคนิคและแผนพิสูจน์](docs/technical_direction.md) · [GDD เดิม](docs/archive/game_design_document_v1_2026-10-14.md)

## 1. สิ่งที่เจ้าของโครงการต้องการ และคำตัดสินรอบนี้

สิ่งที่ยืนยันแล้ว:

- ต้องอ้างอิงแผนที่และสร้าง community เป็นหัวใจ
- คนทุกจังหวัดและพื้นที่ต้องมีทางเล่นที่สนุก ไม่ต้องอยู่ใกล้แลนด์มาร์กดัง
- ทุกคนเลือกบทบาทในเกมได้อิสระ ไม่ผูกกับอาชีพจริง
- เปลี่ยน concept และเอกสารเดิมได้ทั้งหมด
- ยังอยู่ช่วงคิด concept และ stack; การลงมือครั้งต่อไปควรเริ่มจากต้นแบบที่พิสูจน์ความสนุก

คำตัดสินออกแบบที่เสนอภายใต้ขอบเขตนี้:

- เลือกย่านและเล่นจากที่ไหนก็ได้ การเดินทางจริงเป็นส่วนเสริมภายหลัง
- ความก้าวหน้ามีทั้งบ้าน/ร้านส่วนตัว ทักษะ และผลงานร่วมของชุมชน
- เกมหลักเป็นการร่วมมือ มีโจทย์ให้คิดและแสดงตัวตน ไม่ใช้สงครามยึดพื้นที่เป็นเครื่องยนต์หลัก
- ให้ผู้เล่นลงมือทำบทบาทเอง มีผู้ช่วย NPC สำหรับงานที่ตั้งไว้ตอนออฟไลน์
- เริ่มด้วยแผนที่ 2D ที่มีสไตล์และฉากย่าน pixel/isometric ไม่ผูกความสนุกกับการสร้างตึกจริง 3D ครบประเทศ
- ชื่อใหม่เป็นชื่อทำงาน ยังไม่ได้ตรวจเครื่องหมายการค้าหรือโดเมน

## 2. Concept ในหนึ่งย่อหน้า

ประเทศไทยมีโลกพิกเซลซ้อนอยู่ เกิดจากความทรงจำและกิจกรรมเล็ก ๆ ของผู้คน ผู้เล่นเลือกย่านที่รู้สึกผูกพัน ตั้งบ้านหรือร้าน แล้วเป็นคนปลูก คนปรุง ช่างสร้าง คนส่งของ นักสำรวจ หรือคนจัดงาน ผลงานของแต่ละคนต่อกันเป็นสวน ตลาด นิทรรศการ และเทศกาลที่เห็นได้จริงในฉากย่าน เชื่อมกับเพื่อนต่างจังหวัดผ่านการฝากของ คำขอ และการเดินทางเสมือน ทุกคนมีจังหวะของตัวเองและกลับมาเห็นว่า “สิ่งที่ฉันทำมีคนใช้ และทำให้ที่นี่เปลี่ยนไป”

**Player fantasy:** มีที่ของตัวเองในประเทศไทยฉบับอบอุ่น มีฝีมือที่คนอื่นจำได้ และมีเพื่อนร่วมสร้างเรื่องราว

**อารมณ์:** อบอุ่น สนุก ขี้เล่น มีเรื่องให้ค้นพบ มีความท้าทายจากการเลือก ไม่กดดันด้วยการสูญเสียเมื่อไม่ได้ล็อกอิน

**แกนความสนุกสามข้อ:** ฉันเลือกได้ → ผลงานมีรูปร่าง → คนอื่นรับรู้และต่อยอดได้

## 3. ทำไมทิศทางนี้เหมาะกับโจทย์

ข้อมูลไทยที่ใช้ประกอบอยู่ใน [รายงานวิจัย](docs/thailand_research.md): การเข้าถึงดิจิทัลต่างกันตามวัย/พื้นที่ ชีวิตการทำงานมีหลายรูปแบบ และกิจกรรมชุมชนมีวัตถุดิบมากกว่าแหล่งท่องเที่ยวดัง ข้อมูลเหล่านี้สนับสนุนการออกแบบที่เข้าถึงง่ายและไม่บังคับเวลา แต่ยังไม่พิสูจน์ว่าผู้เล่นต้องการ concept นี้

| ทางเลือก | จุดแข็ง | ข้อขัดกับเป้าหมาย | คำตัดสิน |
|---|---|---|---|
| เกมเดินเก็บของตาม GPS | เชื่อมการออกไปข้างนอกได้ชัด | คนเดินทางไม่สะดวกและพื้นที่ POI น้อยอาจเสียเปรียบ | ใช้เป็นกิจกรรมเสริมหลังพิสูจน์แกนเกม |
| Tycoon + ยึดแลนด์มาร์กตาม GDD เดิม | เป้าหมายโตและการแข่งขันชัด | บทบาทแคบ ชุมชนเสี่ยงกลายเป็นการแข่งขันกำลังเงิน | เก็บการผลิตและส่งของ เปลี่ยนแกนสังคม |
| ชีวิตหลายบทบาท + สร้างย่านร่วมกัน | มีพื้นที่ให้ความถนัดหลายแบบและความผูกพัน | ต้องแก้ cold start และทำให้การช่วยกันสนุกจริง | เลือกสร้างต้นแบบแนวนี้ |

## 4. คำสัญญาต่อผู้เล่น

1. เลือกที่ที่อยากผูกพันได้ โดยไม่ต้องเปิดเผยที่อยู่จริง
2. ทุกพื้นที่มีงานและสิ่งจำเป็นครบ คนอยู่คนเดียวก็เริ่มได้
3. เลือกและเปลี่ยนบทบาทได้โดยไม่เสียเงินหรือเสียความก้าวหน้าเดิม
4. เพื่อนช่วยเพิ่มความหมาย แต่ไม่เป็นเงื่อนไขบังคับให้ผ่านเนื้อหาหลัก
5. พักเกมแล้วบ้านไม่พัง ของไม่เน่า และไม่ต้องจ่ายเพื่อหยุดการลงโทษ
6. จ่ายเพื่อความสวยงามและการสนับสนุน ไม่ซื้ออำนาจเหนือคนอื่น
7. เห็นได้ว่าใครช่วยอะไร โดยไม่เปิดเผยตำแหน่งจริงหรือทำให้คนเล่นน้อยอับอาย

วิสัยทัศน์คือเข้าถึงคนหลากหลายวัยและอาชีพ กลุ่มทดลองรอบแรกเสนอให้ใช้ผู้ใหญ่ 18+ หลายช่วงวัย การเปิดให้ผู้เยาว์ในบริการจริงต้องกำหนดนโยบายและระบบดูแลก่อน ไม่ถือว่าตัดสินช่วงอายุเปิดตัวแล้ว

## 5. แผนที่ทำหน้าที่อะไรในเกม

### 5.1 โลกสองระดับที่เชื่อมกัน

**แผนที่ประเทศไทย:** ใช้ดูพื้นที่ เลือกบ้านหลัก เยี่ยมชุมชน รับงานตามปลายทาง วางแผนการส่ง และสะสมเรื่องราว มีถนน แม่น้ำ ชื่อพื้นที่ และจุดจริงที่ตรวจสอบได้ตามข้อมูลที่มี

**ฉากย่านพิกเซล:** พื้นที่เล่นที่ออกแบบเพื่อความสนุก มีบ้าน ร้าน แปลงปลูก ลานกลาง และ NPC อ้างอิงย่านที่เลือก แต่ไม่จำลองกรรมสิทธิ์หรือผังบ้านจริง ทุกจุดเกมสมมติมีสัญลักษณ์แยกจากจุดจริง

แตะหมุดย่านบนแผนที่เพื่อเข้าไปเห็นฉากที่เปลี่ยนจากผลงานของผู้เล่น กลับออกมาจะเห็นไอคอนโครงการและเส้นทางที่กำลังเชื่อมชุมชน ไม่จำเป็นต้องเรนเดอร์สองโลกพร้อมกัน

### 5.2 แผนที่มีผลต่อการตัดสินใจอย่างไร

- งานส่งของมีต้นทาง/ปลายทางจริงในระดับย่าน และเลือกส่งใกล้หลายงานหรือไกลแบบรวมเที่ยว
- ระยะทางใช้จัดกลุ่มเส้นทางในเกมและงบเที่ยว ไม่จำลองเวลาขับรถจริงแบบ 1:1
- ของสะสมและเรื่องเล่ามีความเกี่ยวข้องกับพื้นที่และมีที่มา
- โครงการคู่ชุมชนทำให้เกิดเหตุผลไปเยี่ยมและรู้จักพื้นที่อื่น
- สวน ร้าน หรือสถานที่ที่สร้างเสร็จเปลี่ยนหน้าตาหมุดและฉากของชุมชนนั้น

การเปิดดูและเยี่ยมพื้นที่อื่นไม่มีค่าตั๋ว ส่วนการส่งสินค้าเป็นงานที่ใช้ช่องการผลิต/การส่งเหมือนบทบาทอื่น ระบบรับประกันตัวเลือกเส้นทางสั้น กลาง และไกลที่มีผลตอบแทนต่อความพยายามใกล้เคียงกันทุกบ้านหลัก ไม่บังคับเริ่มใหม่เมื่อย้ายย่าน

ถ้าตัดแผนที่ออกแล้วผู้เล่นไม่รู้สึกสูญเสียอะไร แปลว่าต้นแบบยังไม่บรรลุเป้าหมายนี้

### 5.3 แยกสถานที่ออกจากกลุ่มเพื่อน

- `พื้นที่`: ตำแหน่งอ้างอิงทางภูมิศาสตร์ ไม่ใช่ข้อมูลว่าผู้เล่นอยู่ที่นั่นจริง
- `ชุมชน`: กลุ่มผู้เล่น มีพื้นที่บ้านหลักและฉากส่วนกลางของตน
- พื้นที่เดียวมีหลายชุมชนได้ ไม่มีใครจับจองที่จริงจนคนอื่นเล่นไม่ได้
- สมาชิกมาจากจังหวัดใดก็ได้ และมีบ้านส่วนตัวคนละพื้นที่ได้
- MVP มีชุมชนหลักได้หนึ่งกลุ่มต่อบัญชี เยี่ยมชุมชนอื่นได้ตามสิทธิ์
- แผนที่สาธารณะแสดงเฉพาะชุมชนที่เปิดให้ค้นพบและข้อมูลที่ยินยอมเผยแพร่ ไม่แสดงพิกัดผู้เล่นออนไลน์

**ตัวอย่าง:** ผู้เล่นอยู่ระยองเลือกบ้านพิกเซลที่ลำปาง และอยู่ชุมชนเพื่อนซึ่งมีลานกลางอ้างอิงพัทลุงได้ นี่เป็นการเดินทางและสังกัดในเกม ไม่ใช่การปลอม GPS

### 5.4 สัญญาความเท่าเทียมของพื้นที่

ทุกย่านต้องมีแปลงปลูก ครัว โรงงานช่าง จุดส่งของ NPC กระดานงาน และโครงการเริ่มต้น แม้ข้อมูล POI เป็นศูนย์ ใช้จุดเกมเสมือนที่มีป้ายชัดเจน ไม่วางเป็นหมุดร้านจริงโดยอ้างว่ามีอยู่จริง

ความหนาแน่น POI จำนวนประชากร ราคาที่ดิน และยอดเงินเติม ไม่เพิ่มกำลังผลิตพื้นฐาน ทุกอาชีพเล่นได้ทุกภูมิภาค ภูมิศาสตร์เปลี่ยนธีมและเส้นทาง ไม่กำหนดชนชั้นผู้เล่น

พื้นที่ภูเขา เกาะ หรือจุดที่ระบุย่านไม่ได้ยังเลือกพื้นที่อ้างอิงใกล้เคียงหรือระดับอำเภอ/จังหวัดเพื่อเปิดฉากได้ การเล่นไม่ได้อนุญาตหรือแนะนำให้เข้าพื้นที่จริงนั้น

## 6. ช่วงแรกที่ผู้เล่นจะได้เล่น

ตัวอย่างสมมติ ไม่ใช่ภาพจากเกมที่สร้างแล้ว:

> คุณเลือกย่านบ้านเกิดและเปิดร้านเล็ก ๆ วันนี้ NPC อยากชวนทุกคนจัด “ตลาดเย็นวันแรก” คุณเลือกเป็นคนปรุง ตัดสินใจทำอาหารชุดประหยัดวัตถุดิบหรือชุดที่ตกแต่งได้มากกว่า เพื่อนอีกคนทำโต๊ะ ส่วนอีกคนรวมของขึ้นรถไปส่ง เมื่อครบหนึ่งช่วง ลานว่างกลายเป็นมุมร้านที่มีคนเดินผ่าน กลับมาอีกวันเห็นโปสต์การ์ดว่าอาหารของคุณถูกจัดอยู่บนโต๊ะที่เพื่อนสร้าง และกดส่งสติ๊กเกอร์ขอบคุณกันได้

ลำดับเป้าหมายของ onboarding:

1. เปิดลิงก์ → เลือกจังหวัด/ค้นย่าน/เลือกย่านตัวอย่าง โดยไม่ขอ GPS อัตโนมัติ
2. เลือกความสนใจหนึ่งอย่างและตัวละคร เริ่มด้วยบทบาทแนะนำแต่เปลี่ยนได้
3. ได้ทำการตัดสินใจแรกภายในเป้าหมาย 3 นาที เลือก 1 งานจาก 2 ทางเลือกที่มีข้อแลกเปลี่ยนชัด
4. ทำงานแรกแบบทันทีเพื่อเห็นผล ไม่พบกำแพงรอเวลาใน tutorial
5. เลือกวางของในพื้นที่ส่วนตัวหรือส่งให้โครงการเริ่มต้น แล้วเห็นผลตามทางที่เลือก การส่งใช้ของหนึ่งครั้งและเก็บภาพ/เครดิตเป็นความทรงจำ ไม่เพิ่มของสำเนาในบ้าน
6. ถ้ามาจากคำชวน แสดงว่าชุมชนเพื่อนกำลังทำอะไร; ถ้ายังไม่มีเพื่อน ใช้ NPC ที่มีป้ายระบุชัด
7. ให้ตั้งงานล่วงหน้าและบอกว่าจะได้อะไรเมื่อกลับมา ไม่มี countdown เร่งให้สมัครหรือซื้อ
8. ให้บันทึกบัญชีก่อนเข้าร่วมระบบชุมชนถาวร; guest preview ไม่สามารถย้าย inventory ที่แก้เองจากเครื่องเข้าเศรษฐกิจจริง

| 3–8 นาที | เลือกงาน ลงมือหนึ่งขั้น ส่งผลงาน แต่งมุมเล็ก ๆ | ได้ตัดสินใจและเห็นผล ไม่ต้องเล่นยาว |
| กลับมาวันอื่น | รับงานที่ตั้งไว้ ดูการต่อยอดของเพื่อน เริ่มชุดงานใหม่ | มีเรื่องให้รอดู แต่ไม่ค้างหนี้งาน |
| หลายวัน | ร่วมสร้างโครงการหรือเชื่อมย่านคู่กัน | จำคนที่ช่วยและเห็นผลงานร่วม |
| ระยะยาว | ขยายวิธีทำงาน แต่งบ้าน เก็บสมุดเรื่องย่าน | ตัวตนชัดขึ้น ไม่ใช่แค่ตัวเลขใหญ่ขึ้น |

### ข้อแลกเปลี่ยนที่ต้องมีในทุกบทบาท

- ทำงานสั้นที่รับผลได้เร็ว หรือรวมชุดที่มีตัวเลือกตกแต่งมากขึ้น
- ใช้วัตถุดิบทำของส่วนตัวหรือส่งมอบให้โครงการที่อยากเห็นสำเร็จ
- เลือกของที่เข้ากับคำขอของผู้รับ ไม่ใช่สูตรแพงสุดชนะเสมอ
- ใช้ช่องงานกับหนึ่งแผน จึงต้องเลือก แต่ไม่มีการซื้อช่องเพื่อเอาเปรียบ

งานมีระดับสำเร็จที่รู้ล่วงหน้า ไม่สุ่มทำของเสีย ผู้เล่นอ่านผลตอบแทนและเวลาจบก่อนกดยืนยัน มินิเกมการจัดวาง/จับคู่มีได้เพื่อความสนุก แต่ห้ามใช้ความเร็วมือเป็นกำแพงผ่านเนื้อหาหลัก

## 8. บทบาทอิสระและการพัฒนาฝีมือ

| บทบาท | การตัดสินใจเฉพาะ | สิ่งที่ส่งต่อให้คนอื่น | ขอบเขต |
|---|---|---|---|
| คนปลูก | จัดพื้นที่ปลูกและเลือกชุดพืชให้ตรงงาน โดยมีช่องแปลงจำกัด | วัตถุดิบ ดอกไม้ มุมสวน | MVP |
| คนปรุง | เลือกสูตรและวัตถุดิบทดแทนตามความต้องการของงาน | อาหาร/เครื่องดื่มสำหรับตลาดและงานเลี้ยง | MVP |
| ช่างสร้าง | เลือกแบบ วัสดุ และตำแหน่งวางภายใต้งบชิ้นส่วน | เฟอร์นิเจอร์ ป้าย ของใช้ในลานกลาง | MVP |
| คนส่งของ | รวมคำขอ เลือกลำดับปลายทางและจัดพื้นที่บรรทุก | ส่งผลงานถึงผู้รับ พร้อมบันทึกเส้นทาง | MVP |
| นักสำรวจและนักเล่าเรื่อง | เลือกเส้นทางค้นเรื่อง จับคู่ร่องรอยกับบันทึกที่ตรวจสอบแล้ว | หน้าใหม่ในสมุดเรื่องย่าน/นิทรรศการ | หลัง MVP; การเยี่ยมแผนที่พื้นฐานเปิดทุกคน |
| คนจัดงาน | จัดรูปแบบงาน เลือกชุดอาหาร ของตกแต่ง และพื้นที่จากหลายบทบาท | เทศกาล/ตลาด/กิจกรรมชุมชนแบบปรับแต่งได้ | หลัง MVP; MVP ใช้ template งานสำเร็จรูป |

เปลี่ยนบทบาทฟรี ใช้คิวงานรวมต่อบัญชีเดียว ไม่ได้เพิ่มจำนวนคิวด้วยการสลับบทบาท งานที่เริ่มแล้วใช้สูตรและกติกาตอนเริ่ม ไม่ถูกเปลี่ยนผลกลางทางเพราะเปลี่ยนอาชีพ

ค่าฝีมือปลดล็อกสูตร รูปแบบ และวิธีจัดงาน ไม่ทวีคูณพลังจนมือใหม่ไม่มีประโยชน์ ทุกโครงการมีช่องงานพื้นฐานที่ผู้เล่นใหม่ช่วยได้ตั้งแต่วันแรก และทุกบทบาททำงานให้ NPC ได้เมื่อไม่มีคนรอรับ

ตัวละครผู้ช่วยปลดล็อกผ่านเรื่องราว เลือกนิสัย/งานถนัดได้ ไม่มีระดับความหายากแบบซื้อสุ่มเพื่อปลดล็อกข้อได้เปรียบ

## 9. ระบบชุมชน: ให้เกิดความสัมพันธ์จากสิ่งที่ทำ

### 9.1 คำขอที่เห็นผู้รับ

แทนกระดานที่มีแต่จำนวนสินค้า ให้เห็น “ใครกำลังทำอะไรและของนี้จะไปอยู่ตรงไหน” เช่น “เมย์กำลังทำมุมอ่านหนังสือ ต้องการโต๊ะอีกหนึ่งตัว” หลังส่งสำเร็จมีภาพวางโต๊ะและปุ่มขอบคุณ ไม่บังคับตอบข้อความ

ตั้งคำขอจาก recipe/template ที่ระบบอนุญาตเท่านั้นใน MVP ผู้เล่นไม่สามารถใส่จำนวนรางวัลเองหรือส่งเงินข้ามบัญชีได้

### 9.2 ลานกลางและโครงการร่วม

เริ่มด้วยกลุ่มเล็กเป้าหมาย 8–20 คน แต่ไม่ต้องครบจำนวนจึงเริ่มได้ มี 1 โครงการหลักที่กำลังทำ เช่น ตลาดเย็น สวนพักใจ หรือห้องจัดแสดงเรื่องย่าน

แต่ละโครงการแบ่งเป็นช่วงเล็ก มีผลที่มองเห็นทุกช่วง สูตรพื้นฐานสำหรับต้นแบบ: 4 หมวดงาน × 3 หน่วยส่งมอบ = 12 หน่วยต่อช่วง ไม่ใช่ตัวเลขบาลานซ์สุดท้าย สมาชิกหนึ่งคนทำให้ครบเองได้โดยสลับบทบาทหรือใช้ความช่วยเหลือ NPC ที่เปิดให้ทุกคนเท่ากัน จึงไม่มีจำนวนสมาชิกขั้นต่ำหรือ deadline บังคับ

การรับส่งสินค้ากับเพื่อนต้องลดการทำซ้ำและทำให้เกิดเครดิตผู้ร่วมสร้าง โดยผลตอบแทนเศรษฐกิจต่อความพยายามไม่พุ่งตามจำนวนสมาชิก ไม่มีรางวัลตามอันดับยอดบริจาค

เริ่มจากโครงการขนาดคงที่เพื่อความเข้าใจง่าย ยังไม่ใช้สูตรปรับความยากตาม active users เพราะอาจกลายเป็นแรงจูงใจให้เตะสมาชิกหรือแบ่งกลุ่มฟาร์ม

### 9.3 อำนาจจัดการและการย้ายกลุ่ม

- บ้านและของส่วนตัวเป็นของบัญชี เจ้าของกลุ่มแตะไม่ได้
- ของที่ส่งมอบแล้วระบุชัดว่าเป็นผลงานส่วนกลางและถอนไม่ได้หลังยืนยัน แต่ไม่โอนเข้ากระเป๋าหัวหน้ากลุ่ม
- MVP ใช้ layout ลานกลางสำเร็จรูปและตัวเลือกตกแต่งรายจุด ลดปัญหาคนหนึ่งรื้อของอีกคน
- การเลือกโครงการใช้โหวตจากตัวเลือกที่ทุกคนเห็น; หากไม่ลงคะแนนใช้ตัวเลือกเริ่มต้นที่ประกาศไว้ ไม่มีงานค้างเพราะขาด quorum
- ออกจากกลุ่มได้โดยเก็บบ้าน ฝีมือ ของส่วนตัว และสำเนาสมุดผลงานร่วมไว้
- การเตะสมาชิกต้องมีเหตุผลและบันทึก พร้อมช่องรายงาน; ไม่ลบเครดิตผลงานเดิมของเขา
- ผู้เล่นเลือกซ่อนชื่อบนผลงานได้ การลบบัญชีทำให้เครดิตเป็นนิรนามตามนโยบายเก็บข้อมูลที่ต้องกำหนดก่อนเปิดจริง

### 9.4 การสื่อสารในรุ่นแรก

คำขอสำเร็จรูป สติ๊กเกอร์ขอบคุณ ปฏิกิริยา และคำชวนแบบลิงก์เพียงพอสำหรับทดลองสมมติฐาน community ก่อน มี block/report และคิวตรวจชื่อผู้เล่น/ชื่อกลุ่มตั้งแต่เปิดทดสอบกับคนอื่น

ไม่มีแชตสาธารณะระดับประเทศ DM รูปอัปโหลด หรือเสียงใน MVP เพิ่มเมื่อมีหลักฐานความต้องการและคนดูแลจริง การร่วมมือไม่ควรบังคับใช้แอปแชตภายนอก

## 10. ไอเดียเอกลักษณ์ที่ควรทดลอง

| ไอเดีย | สิ่งที่ผู้เล่นได้ทำ | ทำไมจึงน่าสนใจ | ระยะ |
|---|---|---|---|
| **ของชิ้นนี้ผ่านมือใครบ้าง** | แตะของในงานแล้วเห็นผู้ปลูก ผู้ปรุง ผู้ส่ง หรือผู้สร้างตามขั้นที่มีจริง | ทำให้ห่วงโซ่งานมีคนและความทรงจำ ไม่ใช่ตัวเลข | MVP แบบสั้น ไม่บันทึกข้อมูลส่วนตัวจริง |
| **โปสต์การ์ดที่เกิดจากการร่วมมือ** | ได้ภาพลานก่อน/หลังพร้อมผลงานที่แต่ละคนเลือกให้แสดง | เป็นของสะสมของเรื่องที่เกิดขึ้นจริงในเกม และแชร์คำชวนได้ | MVP |
| **แฝดย่าน คนละจังหวัด** | ชุมชนจับคู่ทำโครงการข้ามพื้นที่ เช่น แลกแบบโต๊ะกับชุดของกิน แล้วเก็บภาพคู่ | ทำให้แผนที่และการรู้จักคนต่างถิ่นมีเหตุผล | หลังพิสูจน์ชุมชนเดี่ยว |
| **สมุดบ้านเกิด** | สะสมหน้าความทรงจำของร้านแรก งานแรก และเพื่อนที่ร่วมงาน | มีเหตุผลกลับมาที่เดิมโดยไม่ต้องยึดครองพื้นที่ | MVP 1 ชุดเรื่องเริ่มต้น |
| **ตลาดที่เดินทางไปหาเพื่อน** | รวมผลงานเป็นขบวนตลาดเสมือน เยี่ยมย่านปลายทางตามที่เลือก | ให้คนส่งของและคนจัดงานมีบทบาทที่มองเห็นบนแผนที่ | หลัง MVP |
| **ภูตประจำย่าน** | ทำเรื่องราว/งานหลายแบบจนรู้จักมาสคอตที่มีบุคลิกและความชอบ | เก็บเสน่ห์ Street Pixels จาก concept เดิม โดยไม่ขายพลังสุ่ม | หลัง MVP; เริ่มด้วย NPC ไม่กี่ตัว |

ไอเดียเหล่านี้เป็น backlog ไม่ใช่ข้อผูกมัดให้ทำพร้อมกัน ห้ามเพิ่มระบบก่อนพิสูจน์ว่า loop แรกสนุก

## 11. เศรษฐกิจและเวลาชีวิต

### 11.1 ทรัพยากรเริ่มต้น

- **เหรียญ:** ได้จากงานที่ระบบรับรอง ใช้ซื้อแบบตกแต่งและวัตถุดิบพื้นฐานจาก NPC ไม่ซื้อด้วยเงินจริงใน MVP
- **วัตถุดิบ/ผลงาน:** ผลจากการเล่น ใช้เองหรือส่งมอบตามคำขอ จำนวนรับ–จ่ายต้องตรวจสอบได้
- **ฝีมือ:** ความก้าวหน้าของบทบาท โอนไม่ได้และซื้อไม่ได้
- **บันทึกความร่วมมือ:** หลักฐานสิ่งที่ทำ ไม่เป็นเหรียญซื้อเสียงหรือคะแนนจัดอันดับคนดี

ยังไม่มี premium currency, free-price auction, เงินสดถอนออก, NFT หรือการจ้างงานจริง

### 11.2 ตัวอย่างเศรษฐกิจที่ต้องจำลองก่อนใช้

ตัวเลขต่อไปนี้เป็นตัวอย่างทดสอบ ไม่ใช่ราคาสุดท้าย: คนปรุงใช้วัตถุดิบ 2 หน่วยทำอาหาร 1 ชุด เลือกใช้เองหรือส่งคำขอครั้งเดียว เมื่อส่งแล้วสินค้าถูกใช้และจ่ายเหรียญตามงานหนึ่งครั้ง; ถ้ามีผู้ส่งของ ให้จ่ายค่าบริการจากงบรางวัลที่กำหนดไว้ ไม่จ่ายรางวัลขายเต็มซ้ำทั้งตอนส่งและตอนรับ

การส่งของให้เพื่อนไม่สร้างเหรียญจากการวนส่งชิ้นเดิม บันทึก provenance อาจอยู่ต่อเป็นความทรงจำได้แม้ item ถูกใช้แล้ว และการเห็นเครดิตไม่แปลว่าเป็นเจ้าของ item หลายสำเนา

สินค้าพื้นฐานเข้าถึงได้จาก NPC เสมอ รางวัล/ต้นทุนระบบต้องไม่มีวงจรซื้อ–แปรรูป–ขายกลับที่ทำกำไรไม่จำกัดโดยไม่ใช้ช่องงานหรือเวลา ทดสอบการปั๊มบัญชี การโอนวน และการกดรับซ้ำก่อนเปิดเศรษฐกิจร่วม

### 11.3 ออฟไลน์และการพักเกม

- คิวงานล่วงหน้าเป้าหมายไม่เกิน 24 ชั่วโมงต่อชุด เปิดเท่ากันสำหรับทุกคน ผลที่ทำเสร็จไม่หมดอายุ
- คิวใช้วัตถุดิบและจำนวนงานจำกัด จบแล้วหยุด ไม่ฟาร์มไม่สิ้นสุด
- ผู้เล่นไม่ได้เข้าหลายวันไม่เสียบ้านหรือความก้าวหน้า ยอมรับว่าได้ผลผลิตน้อยกว่าคนเล่นต่อเนื่อง แต่ไม่มีโทษย้อนหลัง
- ไม่มี daily streak แบบขาดแล้วเสียของ ไม่มีภารกิจหลักที่ต้องเข้า 22:00–04:00 และไม่มีของเน่า
- เทศกาลมีเรื่องหลักให้กลับมาเล่นในคลังย้อนหลังได้ ส่วนกิจกรรมชุมชนตามฤดูกาลไม่รีเซ็ตบ้านหรือฝีมือ
- ระบบคำนวณเวลาจาก server ไม่ต้องเปิด browser ค้างไว้ ไม่อ้างว่า PWA รันเกมต่อเบื้องหลัง

## 12. โทนภาพและการเข้าถึง

แผนที่สีอุ่น อ่านถนนและชื่อได้ชัด ฉากย่านเป็น pixel/isometric มี animation เล็ก ๆ ที่อธิบายว่างานเกิดอะไรขึ้น บ้าน สวน ร้าน และพื้นที่ชนบทได้รับความใส่ใจพอ ๆ กับเมืองใหญ่

ภาษาไทยเป็นหลัก ปุ่มใช้กริยาสั้น ๆ เช่น ปลูก ทำ ส่ง เยี่ยม เก็บ มีตัวหนังสืออ่านง่าย ไม่ใช้ pixel font สำหรับย่อหน้ายาว

- มีทางแตะเลือกต้นทาง/ปลายทางแทนการลากเส้น
- การเล่นสำคัญมี DOM UI และ list view แทนการต้องอ่าน canvas อย่างเดียว
- ไม่ใช้สีอย่างเดียวแยกวัตถุดิบ/สถานะ รองรับลด motion และปิดเสียง
- โหมดประหยัดใช้ภาพนิ่งและรายละเอียดต่ำ เป้าหมาย 30 FPS; โหมดเต็มเป็นทางเลือก
- แผนที่โหลดไม่สำเร็จยังเปิดรายการงานและดูสถานะล่าสุดที่ติดป้ายเวลาได้ แต่การใช้/รับของต้องยืนยันกับ server
- ไม่เหมารวมจังหวัดเป็น stereotype; ชุดศิลป์และเรื่องราวมีผู้ตรวจเนื้อหาก่อนเผยแพร่

## 13. โลกจริง ตำแหน่ง และความไว้ใจ

MVP ไม่เก็บ GPS เพื่อเริ่มเล่น ใช้ย่านที่ผู้เล่นเลือก อาจเพิ่มปุ่ม “หาพื้นที่ใกล้ฉัน” แบบสมัครใจภายหลัง โดยไม่แสดงพิกัดนั้นให้คนอื่นและไม่เก็บประวัติการเคลื่อนที่

ไม่มีใครเป็นเจ้าของร้าน/บ้านจริงจากการวางของในเกม และไม่มีแผนที่ไล่ดูว่าผู้เล่นกำลังอยู่ตรงไหน โปสต์การ์ดแชร์ชื่อพื้นที่ในเกมและชื่อที่ผู้เล่นเลือกเท่านั้น

จุดเยี่ยมจริงในอนาคตต้องได้รับการคัดเลือก ไม่ใช้หมุดสุ่มเพื่อชวนเข้าเขตส่วนบุคคลหรือพื้นที่อันตราย รางวัลที่มีผลกับ progression หาได้ด้วยการเล่นออนไลน์เช่นกัน ไม่มีสัญญาว่า GPS พิสูจน์การไปถึงจริงได้แน่นอน

ต้องมีเจ้าของงาน moderation และวิธีรับรายงานก่อนเปิด community ต่อสาธารณะ ข้อมูลกฎหมาย/อายุผู้เล่น/การชำระเงินเป็นเรื่องตรวจเฉพาะก่อนเปิดบริการ ไม่อ้างว่าเอกสารนี้รับรอง compliance

## 14. รายได้ที่ไม่ทำลายเหตุผลที่อยากเล่น

ข้อเสนอหลังพิสูจน์ความสนุก: ชุดแต่งบ้าน เสื้อผ้า ธีมร้าน animation และแพ็กสนับสนุนที่เห็นสิ่งที่จะได้ชัด ซื้อแล้วไม่เพิ่มจำนวนคิว คะแนนโครงการ ความเร็ว หรืออำนาจจัดการชุมชน

ของแต่งฟรีต้องทำให้บ้านดูมีบุคลิกได้จริงก่อนขายของแต่งเพิ่ม ไม่ขายความสามารถเข้าถึงพื้นที่หรือการเปลี่ยนอาชีพ ไม่เก็บเงินเพื่อเพิ่ม offline cap

ผู้สนับสนุนร้านจริงเป็นทางเลือกอนาคต ต้องแสดงว่าเป็นเนื้อหาสนับสนุนและไม่ทำให้พื้นที่ไม่มีสปอนเซอร์เสียโอกาส เนื้อหาทุกภูมิภาคมีฐานฟรีอยู่แล้ว ยังไม่ทำคูปอง/ตรวจภาพ AI/ธุรกรรมร้านจริงใน MVP

ยังไม่มีหลักฐาน willingness to pay และไม่มีประมาณการรายได้ที่พิสูจน์แล้ว

## 15. ขอบเขตการพัฒนาและเกณฑ์ผ่าน

ไม่ใช้ roadmap 12 เดือนที่สัญญาระบบเพิ่มก่อนรู้ว่าเกมสนุก ใช้ประตูตัดสินจากหลักฐานแทน ระยะเวลาจริงต้องประเมินหลังต้นแบบแรกและรู้ทรัพยากรทีม

| ระยะ | สิ่งที่ส่งมอบ | เกณฑ์ผ่านก่อนขยาย |
|---|---|---|
| P0 — ทดลองการตัดสินใจ | Prototype เล่นคนเดียว 1 ฉาก, loop ตัวอย่าง 2 บทบาท, เปรียบเทียบ map กับพื้นที่สมมติ | ผู้เล่นอธิบายทางเลือกและผลได้ เห็นว่าทำไมอยากทำงานถัดไป; ถ้ารู้สึกเป็นงานบ้าน ให้แก้ loop |
| P1 — Vertical slice | 4 บทบาท, ย่านตัวอย่างเมืองและนอกเมือง, 1 โครงการ, NPC, บ้านส่วนตัว, คิวงานและบันทึกการส่ง | เล่นโดยไม่ให้ GPS/ไม่มี POI/คนเดียวได้ครบ loop; ผลต่างภูมิศาสตร์ไม่ทำให้ติด progression |
| P2 — Closed community alpha | คนจริง 40–60 คน, หลายชุมชน, คำขอ, เครดิตผลงาน, block/report, persistence และกติกาเศรษฐกิจ | มีการช่วยกันซ้ำโดยสมัครใจ; บัญชี/ของ/รางวัลไม่รั่วหรือซ้ำ; พบเหตุผลกลับมาที่เกินกว่ารับเงิน |
| P3 — Geographic beta | เลือกพื้นที่ทั่วไทย, fallback ย่าน, ชุดตรวจ 77 พื้นที่ระดับจังหวัดและบริบทชายขอบ, ทดสอบเครื่องจริง | ไม่มี geographic lock ในกลไกหลัก; ผ่าน performance/ข้อมูล/ดูแลชุมชนตามเอกสารเทคนิค |
| P4 — เปิดบริการและทดลองรายได้ | เพิ่ม content ที่ผ่าน playtest และร้านของแต่งเมื่อพร้อม | มีเจ้าของงานปฏิบัติการ งบโครงสร้างพื้นฐาน นโยบายบริการ และหลักฐานว่าคนอยากกลับมา |

**MVP เชิงผลิตภัณฑ์คือ P2:** พิสูจน์ชุมชนจริงในพื้นที่ตัวอย่าง โดยโครงสร้างรองรับทุกพื้นที่ตั้งแต่ต้น ส่วนการประกาศรองรับทั่วไทยต้องผ่าน P3 ไม่ใช้ภาพต้นแบบแทนหลักฐาน coverage

MVP ไม่รวมโลก 3D เต็มประเทศ, PvP ยึดดินแดน, paid gacha, ตลาดซื้อขายราคาอิสระ, แชตเปิด, AI สร้างข้อเท็จจริงท้องถิ่น, GPS check-in, สภาพอากาศ/จราจรสด, คูปองร้านจริง หรือ minigame ครบทุกอาชีพ

## 16. วิธีวัดว่าคนเล่นแล้วเกิดชุมชนจริงหรือไม่

**ตัวชี้วัดหลักที่เสนอ:** จำนวนผู้เล่นต่อสัปดาห์ที่มีผลงานของตนถูกผู้เล่นจริงอีกคนใช้หรือต่อยอดในกิจกรรมที่สำเร็จ พร้อมดูสัดส่วนต่อ weekly active users กันตัวเลขโตเพียงเพราะมีคนเข้ามากขึ้น

ไม่นับ NPC ผู้ทดสอบภายใน หรือแค่กดปฏิกิริยาเป็นความร่วมมือที่สำเร็จ บัญชีทดสอบแยกชัดและตรวจพฤติกรรมวนส่งระหว่างบัญชีซ้ำ

เกณฑ์ทดลองต่อไปนี้เป็นสมมติฐานเริ่มต้น ไม่ใช่ benchmark อุตสาหกรรม:

| สิ่งที่วัด | เป้าหมายชั่วคราว | วิธีอ่านผล |
|---|---|---|
| เริ่มทำงานแรกได้ | ผู้ทดสอบ ≥80% ทำเองภายใน 5 นาที | นับผู้เริ่มทั้งหมด รายงานจำนวนจริงด้วย ไม่ลบคนที่สับสนออก |
| บทบาทมีการตัดสินใจ | หลังเล่นอย่างน้อย 3 ใน 4 บทบาท ผู้ทดสอบ ≥70% อธิบายข้อแลกเปลี่ยนของอย่างน้อย 2 บทบาทได้ | ไม่ใช้คำตอบว่า “สนุก” อย่างเดียว |
| เกิดความสัมพันธ์ | ≥50% ของบัญชีที่ผ่าน onboarding มีงานร่วมกับคนจริงอย่างน้อยหนึ่งครั้งภายใน 7 วัน | วัดซ้ำด้วยว่ามีคู่เดิมกลับมาช่วยกันหรือไม่ |
| มีเหตุผลกลับมาเอง | เก็บ D1/D7 พร้อมเหตุผลกลับมา/เลิก | ยังไม่ตั้งเป้ารายได้หรือ retention จากกลุ่มเล็ก; ไม่นับการเข้าเพราะทีมเตือนเป็น organic return |
| ไม่มีพื้นที่เสียเปรียบเชิงระบบ | fixtures ที่ไม่มี GPS/ไม่มี POI/มีคนเดียวผ่าน core flow ทุกกรณีที่กำหนด | เป็น correctness gate; ไม่ใช้ค่าเฉลี่ยกลบพื้นที่ที่เล่นไม่ได้ |
| จังหวะไม่กดดัน | สัมภาษณ์หลังหายไป 2–3 วันและตรวจว่ามีของ/สิทธิ์สูญเสียหรือไม่ | ถ้ากลับมาแล้วรู้สึกเป็นภาระ ต้องแก้ก่อนเพิ่ม live events |

ถ้าผู้เล่นชอบแต่งบ้านแต่ไม่อยากร่วมงาน ให้ปรับ interaction และข้อเสนอชุมชน ถ้าชอบร่วมงานแต่แผนที่ไม่มีความหมาย ให้แก้กลไกตามพื้นที่ ถ้าทุกบทบาทเป็นการรอตัวจับเวลา ให้หยุดเพิ่ม content และทำการลงมือเล่นใหม่

## 17. สรุปความต่างจาก GDD เดิม

| เดิม | ฉบับนี้ | เหตุผล |
|---|---|---|
| เจ้าพ่อธุรกิจ/มหาเศรษฐีอันดับหนึ่ง | สมาชิกชุมชนที่มีบ้านและฝีมือของตัวเอง | รองรับแรงจูงใจหลากหลาย |
| GPS รอบตัวและตึกจริงเป็นฐาน | เลือกพื้นที่ผูกพัน + ฉากเสมือนที่เล่นได้ครบ | ลดความได้เปรียบจากทำเลและข้อมูลแผนที่ |
| กาชาพนักงาน | ผู้เล่นหลายบทบาท + NPC ผ่านเรื่องราว | ให้ตัวตนผู้เล่นสำคัญและไม่ขายพลัง |
| ประมูลพื้นที่/ภาษี 2% | โครงการร่วมและเส้นทางระหว่างชุมชน | สร้างเหตุผลช่วยกันตั้งแต่ผู้เล่นใหม่ |
| Offline cap เป็นสิทธิ์รายเดือน | คิวพื้นฐานเท่ากัน ผลผลิตไม่หมดอายุ | เคารพเวลาชีวิต |
| Prestige รีเซ็ตเงิน | สมุดผลงานและทางเลือกใหม่ที่ต่อยอดของเดิม | เก็บความผูกพันกับสิ่งที่สร้าง |
| 3D หลาย engine ซ้อนกันตั้งแต่ต้น | map view และ pixel scene สลับกัน | ให้ทดสอบความสนุกและเครื่องมือถือได้เร็ว |
| Approved for Production | Proposal พร้อมเกณฑ์ทดลอง | สะท้อนสถานะจริงของโครงการ |

## 18. เรื่องที่ยังเปิดอยู่

ไม่ขวางการเริ่มต้นแบบ: ชื่อแบรนด์สุดท้าย โทนภาพละเอียด จำนวนสมาชิกและสูตรบาลานซ์ ค่าเป้าหมาย retention และรายการของแต่งขาย

ต้องตัดสินก่อนเปิดทดสอบวงกว้าง: งบรายเดือนและขนาดกลุ่มทดลอง ผู้รับผิดชอบดูแลชุมชน อุปกรณ์ขั้นต่ำ สิทธิ์ข้อมูล/งานศิลป์ อายุผู้เล่นและข้อกำหนดบริการ วิธีลบบัญชีและระยะเวลาเก็บข้อมูล

**งานพัฒนาถัดไปที่แนะนำ:** สร้าง P0 ที่เล่นได้จริงเพื่อพิสูจน์ “เลือกงาน → ลงมือ → ส่งต่อ → เห็นย่านเปลี่ยน” ก่อนขยายเป็นระบบครบประเทศ
