สถานะ: mockup และสไตล์ภาพ B ผู้สร้างอนุมัติแล้ว หน้าจอจริงทำเสร็จ รอผู้สร้างตรวจ (จุดหยุด #3) ดู `docs/ui/review.md`

ทุกอย่างในเอกสารนี้เป็น **ข้อเสนอ** ยังไม่ใช่ข้อตัดสินใจ ผู้สร้างแก้ได้ทุกข้อ ภาพในแบบจำลองเป็นของวาดชั่วคราวด้วยโค้ด ยังไม่ใช่ภาพจาก PixelLab

## 1. ทำไมต้องออกแบบใหม่

หน้าจอ M2 ใช้งานได้แต่ไม่ได้ออกแบบ ปัญหาที่เห็นจากภาพจริง:

- ฉากต่อสู้เป็นแถบเล็ก สไลม์ซึ่งเป็นพระเอกตัวนิดเดียว ไม่มีบรรยากาศ
- ปุ่มหลัก ("รับของออโต้") ตอนรอมีหน้าตาเหมือนปุ่มที่ใช้ไม่ได้
- ข้อมูลเรียงเป็นแผงข้อความหน้าตาเหมือนกันหมด ไม่มีลำดับสายตา
- คำแนะนำซ้อนหลายกล่อง ไม่รู้ว่าควรทำอะไรก่อน
- ทุกอย่างเป็นการ์ดมุมมน ไม่มีความเป็นเกมพิกเซล

## 2. ทิศทางภาพ: ตลาดโต้รุ่งเชียงใหม่ยามค่ำ

| เรื่อง | ข้อเสนอ | เหตุผล |
|---|---|---|
| บรรยากาศ | ม่วงเข้ม/น้ำเงินกลางคืน + แสงโคมสีส้ม แผงตลาด ไฟประดับ พื้นอิฐ | ตรงกับ GDD (ไฟตลาดกลางคืน, ท่าแพ–ไนท์บาซาร์) ทำให้สไลม์สีเขียวสว่างเด่น |
| สีปุ่มหลัก | ส้มโคม ใช้กับ "สิ่งที่กดได้และสำคัญ" เท่านั้น | ผู้เล่นเรียนรู้เร็วว่าสีส้ม = กดเลย |
| ธาตุ | น้ำฟ้า ไฟส้มแดง ลมขาวฟ้า ดินน้ำตาลส้ม | ใช้ซ้ำทั้งเกม (ป้ายธาตุ ขอบมอน หมุดแผนที่) |
| ความหายากของของ | ธรรมดาเทา · ดีเขียว · หายากฟ้า · ตำนานส้มทอง+เรืองแสง | เข้าใจโดยไม่ต้องอ่านคำ |

| รูปทรง | ขอบมุมแหว่งแบบพิกเซลทุกชิ้น ปุ่มมีสันด้านล่างและจมลงตอนกด | เป็นภาษาเดียวทั้งเกม และเข้ากับภาพจาก PixelLab |
| มุมกล้องฉาก | low top-down ตามมาตรฐานสไตล์ภาพ ข้อ 7.1 | ต้องตรงกับที่ PixelLab ทำ ตัวสไลม์ในฉากจริงอาจต่างจากแบบจำลอง |

ข้อควรระวัง: ห้ามใช้วัดและศาสนสถานเป็นฉากต่อสู้หรือของแต่งตามกติกาโครงการ ฉากในแบบจำลองใช้แผงตลาด ตึกแถว โคม และพื้นอิฐ

## 3. หลักการที่ทุกหน้าต้องผ่าน

1. **พระเอกหนึ่งอย่างต่อหน้า** (ฟาร์ม = สไลม์ในฉาก, สไลม์ = ตัวสไลม์พร้อมของที่ใส่)
2. **ปุ่มหลักหนึ่งปุ่มต่อหน้า** สีส้ม ปุ่มอื่นเป็นรอง
3. **ข้อความสั้น** ไม่เกิน 6 บรรทัดสั้นต่อหน้าจอ (ไม่นับรายการของ) ตัวอักษรหลัก ≥ 14 px
4. **นิ้วโป้งถึง** ปุ่มที่ใช้บ่อยอยู่ครึ่งล่าง พื้นที่กด ≥ 44 px
5. **ของใหม่ต้อง "ดู" ได้ ไม่ใช่อ่าน** ได้ของ = เห็นไอคอนเด้งตามความหายาก ไม่ใช่แถวตัวเลข
6. **กดแล้วต้องมีผลที่เห็น** ทุกปุ่มมีการตอบสนอง
7. **คำแนะนำทีละอย่าง** ริบบิ้นเดียวเรียงตามความสำคัญ + จุดแดงบนแท็บ (แทนกล่องแจ้งเตือนหลายอัน)
8. **ไม่ลงโทษคนที่หายไป** ถุงเต็มแค่เตือน ไม่มีของหาย (ตาม GDD ข้อ 9)

## 4. หน้าจอและการจัดวาง

| หน้า | พระเอก | ปุ่มหลัก | สิ่งที่เปลี่ยนจาก M2 |
|---|---|---|---|
| ฟักไข่ | ไข่เรืองแสงกลางฉากกลางคืน | แตะไข่ | ไม่มีเมนูรบกวน |
| สร้างสไลม์ | ตัวอย่างสไลม์บนแท่น (เปลี่ยนสี/หน้าตาเห็นทันที) | ตัวนี้แหละ! | ปุ่มอยู่โซนนิ้วโป้ง |
| มอนตัวแรก / ส่วนงอก | สไลม์ + มอน / ส่วนงอกโผล่ | กลืนเลย! / ไปฟาร์มกัน | ทั้งจอมีสองตัวกับปุ่มเดียว |
| ฟาร์ม | ฉากต่อสู้ ใหญ่ครึ่งจอ + ปุ่มสกิลออโต้ (แสดงคูลดาวน์) | เก็บของออโต้ | ถุงของออโต้เป็นภาพที่ค่อย ๆ เต็ม แทนแถบข้อความ |
| เก็บของ | ของที่ได้ (หายาก/มอนทองใหญ่ที่สุด) | เก็บเข้ากระเป๋า | เปิดของเป็นจังหวะ ไม่ใช่ตาราง |
| สไลม์ | ตัวสไลม์ใหญ่ + ช่องของแต่ง 4 ช่องรอบตัว | (แจกแต้ม: ปุ่ม +) | ตุ๊กตาแต่งตัว แท่งสถานะพร้อมปุ่ม + |
| เลือกร่าง | สองร่างเทียบกัน | เลือกร่างนี้ | จอเต็ม ผลสามข้อสั้น |
| สกิล | ช่องสกิลเป็นภาพ + แก่นที่รอกลืน | กลืน | ช่องที่ยังไม่เจอเป็นเงา ชวนไปหา |
| กระเป๋า | ตารางไอคอนสีตามความหายาก | สวมเลย | ลูกศรเขียวบอกว่าดีกว่าของที่ใส่ |
| แผนที่ | แผนที่แบบภาพ + หมุดย่าน | ฟาร์มที่นี่ | แทนรายการการ์ด (ของจริงจาก OSM ใน M3) |

ตัวอย่างภาพของทุกหน้าและสถานะ (ปกติ/ถุงเต็ม/เพิ่งเก็บ/ด่านหนักเกิน/เลเวลอัป) อยู่ใน `docs/ui/mockup.html`

## 5. ความรู้สึกตอนเล่น (ทำใน 2.5.4)

| จังหวะ | สิ่งที่เกิดบนจอ |
|---|---|
| สไลม์ตี/โดนตี | ตัวเด้ง ตัวเลขดาเมจลอยขึ้น (คริติคอลใหญ่สีส้ม) มอนกะพริบขาว |
| มอนตาย | แก่นเด้งออกลอยเข้าหาสไลม์ เหรียญกระดอน |
| กลืนแก่น | แก่นถูกดูด ตัวสไลม์ยืดแล้วหด ส่วนงอกโผล่พร้อมประกาย |
| เก็บของออโต้ | ถุงสั่น เปิด ของเด้งทีละชิ้นเรียงตามความหายาก |
| เลเวลอัป / อัปร่าง | จอแฟลช ตัวเลขนับขึ้น / ร่างใหม่ค่อยเผย |
| กดปุ่ม | ปุ่มจมลง 3 px, เสียงสั้นเปิดปิดได้, สั่นเบา ๆ ถ้ารองรับ |

งบประสิทธิภาพ: 30 fps ขึ้นไปบนมือถือระดับกลาง, โหลดครั้งแรกตามงบใน M2.5.5, เคารพ "ลดการเคลื่อนไหว" ของระบบ (ปิดแฟลชและการสั่น)

## 6. สิ่งที่ยังไม่รู้ (ขอให้ผู้สร้างตัดสิน)

1. บรรยากาศตลาดกลางคืนม่วง+ส้ม ใช่ไหม หรืออยากได้อารมณ์อื่น (เช่นสว่างสดใสแบบเกมมือถือ)
2. หน้าฟาร์มที่เห็นสไลม์ใหญ่ครึ่งจอ ดูเป็นเกมขึ้นไหม
3. ปุ่มส้มตัวเดียวต่อหน้า ชัดพอไหม
4. หน้าแผนที่แบบภาพ อยากได้ทิศทางนี้ไหม
5. มีหน้าไหนที่ "ยังเหมือนแอปทั่วไป"

## 7. ข้อจำกัดของแบบจำลองรอบนี้

- ภาพทั้งหมดวาดชั่วคราวด้วยโค้ด ฉากและตัวละครในเกมจริงมาจาก PixelLab (ยังต่อ MCP ไม่สำเร็จ ดูสถานะใน development_plan)
- แผนที่เป็นรูปทรงคร่าว ๆ ไม่ใช่ตำแหน่งจริง
- ยังไม่ได้ทดสอบบนมือถือจริง ตรวจด้วย Chromium ที่ 360 และ 390 px เท่านั้น ฟอนต์ Google ไม่โหลดใน sandbox ที่ทดสอบ (ภาพที่ผมตรวจใช้ฟอนต์สำรอง) จึงต้องดูบนอุปกรณ์จริงอีกครั้ง
- ยังไม่มีเสียง

## 8. ขั้นถัดไป

ผู้สร้างอนุมัติ (หรือสั่งแก้) → 2.5.3 ทดลองสไตล์ภาพกับ PixelLab (รอเชื่อมต่อ) → 2.5.4 ทำหน้าจอใหม่ตามแบบที่อนุมัติ

## 9. สิ่งที่พบในรอบที่ 1 และสถานะในรอบที่ 2

ผู้พัฒนา (ผม) ทบทวนแบบจำลองรอบที่ 1 ตามจริงแล้วพบ:

- ✅ แก้ในรอบ 2: **หน้าฟาร์มไม่มีแถบแรงก์ย่านย่อ** ทั้งที่แผน M2 และ GDD ระบุไว้ นี่คือจุดที่ทำให้เกมต่างจากเกม idle ทั่วไป ต้องมีที่ว่างสำหรับมันตั้งแต่ตอนนี้ (แม้ข้อมูลจริงมาใน M4–M5)
- ✅ ปรับในรอบ 2 (ย้ายปุ่มสกิลมาแถวเดียวกับความคืบหน้าด่าน): ส่วนล่างของหน้าฟาร์มแน่น (การ์ดถุง + ริบบิ้น + แท็บ) ควรลองรวมริบบิ้นเข้ากับแถบแรงก์ หรือซ่อนเมื่อไม่มีอะไรต้องทำ
- ✅ แก้ในรอบ 2 (ช่องเงา + การ์ดบอกว่ากลืนมอนครบปลดสกิล): หน้าสกิลมีพื้นที่ว่างเมื่อมีสกิลน้อย ต้องมีสถานะ "เพิ่งเริ่ม" ที่ไม่โล่ง
- ภาพนี้เป็นของวาดชั่วคราว ตัดสินเรื่องความสวยของภาพไม่ได้จนกว่าจะมี PixelLab

## 10. ไอเดียเสริม (ข้อเสนอ ยังไม่ได้ใส่ใน GDD)
