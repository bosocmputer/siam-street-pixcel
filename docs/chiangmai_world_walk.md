# เมืองเก่าเชียงใหม่ 3D: ขอบเขตและวิธีตรวจรับ

วันที่: 15 ตุลาคม 2569

## ข้อกำหนดที่ผู้สร้างระบุ

เริ่มใหม่จากงานเก่าที่ยกเลิก สร้างคูเมืองสี่เหลี่ยมเชียงใหม่จากแผนที่จริง
ให้ลงไปเดินเล่นได้ก่อน เน้นรายละเอียด ไม่ต้องรอออกแบบระบบ MMORPG ทั้งหมด
ภาพที่ให้สองภาพใช้ตรวจลักษณะพื้นที่และเส้นทาง ไม่ดึงภาพ Google มาทำ texture

## ผลลัพธ์

แอปแยก `apps/chiangmai-world` เปิดด้วย `pnpm dev:world`
ใช้ Three.js 0.186.1, TypeScript, Vite และข้อมูล OSM แบบ snapshot ที่รวมมากับเกม
ไม่มีบัญชี แบ็กเอนด์ หรือคำขอ GPS

## วิธีตรวจรับที่ทำซ้ำได้

1. เปิดฉากครั้งแรก เห็นภาพรวมคูเมืองสี่ด้านและปุ่มเริ่มเดิน
2. กดเริ่มที่ท่าแพ แล้วกด W/ลูกศร ตำแหน่งเปลี่ยนและแผนที่ติดตาม
3. เดินชนกำแพงหรืออาคาร ต้องไม่ทะลุ ไปคูน้ำต้องถูกกั้น ยกเว้นทางข้ามที่มีข้อมูล
4. เลือกแต่ละจุดสำรวจและกดย้าย ตรวจว่าไม่เกิดในตัวอาคาร/คูน้ำ
5. เปิดแผนที่ใหญ่ คลิกตำแหน่งแล้วกลับไปเดินได้
6. สลับมุมสูง แสงเช้า–เย็น และภาพละเอียด–ประหยัด ตรวจผลที่เห็น
7. เปิดวิธีเล่น/ข้อมูลฉากและปิดด้วยคีย์บอร์ด
8. ตรวจ viewport มือถือ ไม่มีเมนูล้น และวงควบคุมสามารถขยับตำแหน่งได้
9. รัน `pnpm test:world` และ `pnpm build:world`

## ข้อจำกัดที่ต้องบอกผู้ทดลอง

เส้นทางและ footprint มาจากข้อมูลจริง แต่ facade/ความสูงส่วนใหญ่ประมาณขึ้น
สถานที่สำคัญไม่ได้เป็นโมเดลสแกน พื้นไม่มีความต่างระดับ ยังเดินเข้าอาคารไม่ได้
เป็นโหมดคนเดียวสำหรับพิสูจน์การเดินและโลก ไม่ใช่ MMORPG ออนไลน์ที่พร้อมเปิดบริการ

## ผลตรวจและบั๊กภาพกระพริบ

- Typecheck และ build ของทุก workspace ผ่าน
- ก่อนแก้ภาพกระพริบ เทสต์ทั้ง repository ผ่าน 142 ข้อ รวมฉากใหม่ 10 ข้อ
- เพิ่ม regression tests 2 ข้อสำหรับผิวหลังคาซ้ำและลายพื้นทางแยก ทั้งสองล้มกับรูปแบบเดิม
  และผ่านหลังแก้ รวมเทสต์ฉากใหม่ 12 ข้อ
- ตรวจใน in-app browser: เดินผ่านประตูท่าแพตามถนนราชดำเนินประมาณ 75 เมตร,
  วงควบคุมที่ viewport 390×844, แผนที่ขยาย และย้ายจุดสำรวจได้
- Console ของแท็บใหม่ไม่มี error/warning หลังแก้
- `eslint` ผ่าน; Prettier ของไฟล์ฉากใหม่ผ่าน ส่วน `pnpm lint` ทั้ง repository
  ติดรูปแบบ `.serena/project.yml` ซึ่งเป็นไฟล์ untracked ที่มีอยู่ก่อนงานนี้ จึงไม่แก้ไฟล์นั้น
- Build มีคำเตือนขนาด bundle ของ 3D engine ยังไม่ได้แยกโหลด engine เพิ่ม

ผู้สร้างพบภาพกระพริบขณะซูม/หมุน ภาพก่อนแก้เห็นลายเส้นรบกวนบนผิวถนนและอาคาร
สาเหตุที่ตรวจพบ: extrusion มีฝ้าบนซ้อนใต้ผิวหลังคา, ผิวทางร่วมระดับเดียวกันที่ใช้
texture UV ต่างจุดกำเนิด และ depth buffer ปกติที่ต้องครอบคลุมโลกไกลถึง 16 กม.
แก้ด้วยการสร้างเฉพาะผนังอาคาร, ใช้ world-space UV ของพื้นร่วมกัน, แยกระดับถนน/ทางเดิน/
ลาน และเปิด logarithmic depth buffer ตาม [Three.js renderer options](https://threejs.org/docs/pages/WebGLRenderer.html)
ตรวจซูม/หมุนในเบราว์เซอร์อีกครั้งแล้วลายรบกวนที่พบหายไป ยังต้องวัดความเร็วบนมือถือจริง
เพราะ depth buffer แบบนี้มีผลต่อการใช้ GPU
