# 05 — Art Bible และระบบ Asset

[สารบัญ](README.md) · [แผนที่](04-real-world-map.md) · [งานพัฒนา](07-development-plan.md)

สถานะ: แนวทางผลิตและบัญชีงานเสนอ ยังไม่ได้สร้างหรือ import asset ตามรายการนี้

## 1. ภาพที่อยากได้

Stylized 3D: อิฐสีอุ่น คูน้ำเขียวอมฟ้า ร่มไม้และแสงเย็น รูปทรงอ่านง่ายในจอมือถือ รอยซ้อนใช้เส้นแสงสีครามและสีทองอ่อนที่ต่างจากเมือง ไม่ทำทุกผิวเป็น neon

รักษา silhouette และขนาดสัมพันธ์ของสถานที่เด่น รายละเอียดบนพื้นกับระดับสายตาสำคัญกว่าของเล็กบนหลังคา ความเป็นเชียงใหม่มาจากเส้นทาง วัสดุ รูปอาคาร ต้นไม้ และจังหวะพื้นที่ ไม่ใช่ติดลายท้องถิ่นเหมารวมทุกอย่าง

ตัวอย่างสีเสนอ: อิฐ `#A8543F`, ปูน `#D6C7AF`, ใบไม้ `#557359`, น้ำ `#4E8A8D`, พลัง `#79DDE8`, เตือนอันตราย `#F18D59` สีเป็น art direction ไม่ใช่สีที่ยืนยันจากการสำรวจ

| ----------- | ------------------------------------------------------------ |
| Environment | ถนน ขอบทาง อิฐ กำแพง ทางข้าม คูน้ำ ต้นไม้ อาคารโมดูล         |
| Landmark    | ประตู/กำแพงต้นแบบที่มีภาพอ้างอิงและสถานะความแม่น             |
| Characters  | avatar setup, NPC สมมติ, ชุดเกราะ และอาวุธ                   |
| Enemies     | สไลม์ 2 แบบ แมลง เงาพเนจร บอส                                |
| Animation   | การเคลื่อน ถือดาบ คอมโบ ตั้งรับ หลบ ชาร์จ ปล่อย โดน ล้ม ช่วย |

## 3. ชุด modular เมืองแรก

สร้าง kit ขนาดสัมพันธ์กับพิกัดจริง: ถนนตรง/แยกและ material ร่วม, ขอบทาง, แผงกำแพงอิฐ, มุมกำแพง, หน้าร้านสมมติ 3 แบบ, หลังคา 3 แบบ, ประตู/หน้าต่าง, รั้ว, ต้นไม้ 3 แบบ, ม้านั่ง, โคม และสมอ

ชิ้นซ้ำใช้ mesh/material ร่วมกัน เปลี่ยนองค์ประกอบและสีอย่างมีขอบเขต ทุกชิ้นมี pivot มาตรฐานและ snap grid ของชุดนั้น ห้ามแก้สเกลสุ่มจนประตูแคบเกิน avatar

ป้ายร้านจริงไม่อยู่ใน MVP ใช้แบรนด์สมมติที่ออกแบบเอง เมื่อมีสิทธิ์ใช้ร้านจริงค่อยสร้าง overlay ไม่แก้โมเดลฐานทั้งเซลล์

## 4. Asset manifest

แต่ละ asset มี ID คงที่ ไม่ให้โค้ดค้นด้วยชื่อที่ศิลปินเปลี่ยนได้ เก็บ Roblox asset ID แยกจาก logical ID และ dev/prod ownership

```yaml
id: asset.weapon.echo_sword
version: 1
category: weapon
displayNameKey: item.echo_sword.name
sourceType: original # original | generated | licensed | surveyed
sourcePath: assets-source/weapons/echo-sword/
creator: pending
rightsRecord: pending
robloxAssetId: null
ownerScope: pending # user หรือ group ที่เลือกจริง
rig: r15-compatible
pivot: grip
collision: simplified
lodVariants: [near, far]
dependencies: [asset.material.echo_metal]
reviewStatus: brief # brief | draft | imported | qa | approved | retired
```

เป็นตัวอย่างข้อมูล ไม่ได้ยืนยันว่า ID นี้ upload แล้ว `pending`, `null` และ dependency ที่ยังไม่มีต้องถูกตรวจพบก่อนส่งงาน ready ใช้เวอร์ชันเพื่อเปลี่ยนรูปลักษณ์โดยไม่เปลี่ยน itemId ของผู้เล่น

## 6. Animation และ Action contract

| Action ID              | แอนิเมชัน/ภาพ    | Marker ฝั่งภาพ      | กติกา                                             |
| ---------------------- | ---------------- | ------------------- | ------------------------------------------------- |
| sword.idle / move      | ถือดาบ เดิน วิ่ง | footstep            | ไม่ทำให้ความเร็วขึ้นกับ FPS                       |
| sword.combo_1..3       | ฟันสามท่า        | swing, trail_on/off | server ใช้ action timeline ไม่เชื่อ marker client |
| sword.guard            | ยกดาบรับและค้าง  | guard_pose          | ผูกกับสถานะรับที่ยืนยัน                           |
| sword.dodge            | ขยับหลบ          | trail_on/off        | ระยะและ invulnerability มาจาก config              |
| sword.crescent_charge  | สะสมพลัง         | charge_loop         | loop ต้องหยุดเมื่อตายหรือยกเลิก                   |
| sword.crescent_release | ปล่อยคม          | release             | projectile มี castId เดียว                        |

ต้องทดสอบ animation priority, blending, attachment ต้น/ปลายดาบ และสัดส่วน avatar ที่รองรับ ตรวจสิทธิ์เจ้าของ animation ให้เกม dev/prod ใช้ได้จริง ไม่ถือว่า preview ได้แล้วผู้เล่นทุกคนจะเห็น

## 7. งบคุณภาพตั้งต้น

ต่อไปนี้เป็น **งบของโครงการที่ต้องปรับด้วย profiling** ไม่ใช่ hard limit หรือ best practice ที่ Roblox รับรองว่าตัวเลขเดียวเหมาะทุกเกม

| ชนิด            | งบเริ่มต้นที่เสนอ                             |
| --------------- | --------------------------------------------- |
| ดาบใกล้กล้อง    | 800–2,000 triangles ต่อชิ้น                   |
| สไลม์ธรรมดา     | 400–1,200 triangles                           |
| บอส             | 4,000–8,000 triangles พร้อม LOD               |
| ชิ้นอาคารโมดูล  | 200–2,000 triangles ตามหน้าที่                |
| Texture ทั่วไป  | 512–1,024 px ใช้ atlas/reuse เมื่อเหมาะ       |
| จุดเด่นเฉพาะ    | 2,048 px เฉพาะผ่านการวัดแล้วว่าคุ้ม           |
| เอฟเฟกต์พื้นฐาน | วัสดุร่วม จำกัดพื้นที่โปร่งใสซ้อน และมีโหมดลด |

ต้องวัด draw calls, transparency, shadow, animation และ memory ร่วมด้วย จำนวน triangles ต่ำอย่างเดียวไม่รับประกันว่าลื่น ปรับตาม [Design for performance](https://create.roblox.com/docs/performance-optimization/design)

## 8. วิธีสร้างด้วย AI

เริ่มจาก brief และภาพอ้างอิงที่มีสิทธิ์ → สร้าง draft → ตรวจ silhouette/ขนาด → ลด geometry และแก้ topology/UV ตามจำเป็น → ทำ collision/LOD → import → ทดสอบในแสงจริงของเกม → อนุมัติ manifest

Roblox Studio มี Importer สำหรับโมเดลและข้อมูลประกอบ เช่น mesh, texture และ rig ตาม [Importer](https://create.roblox.com/docs/studio/importer) แต่ทุก asset ที่สร้างด้วย AI ต้องตรวจผลนำเข้าและสิทธิ์ของแหล่งที่ใช้ ไม่ถือว่าโมเดลที่เห็นสวยในภาพหมุนแล้วจะพร้อมใช้ในเกม

งานที่ procedural เหมาะ: ถนน กำแพง พร็อพซ้ำ อาคารจาก kit งานที่ควรตรวจมือมาก: landmark, มือจับดาบ, animation, topology ตัวละคร และหน้าร้านที่ต้องตรงอ้างอิง

### ตัวอย่าง brief ให้ AI

“ดาบสะท้อนต้นฉบับสำหรับ Action RPG บน Roblox รูปทรงอ่านง่าย คมเหล็กเรียบมีร่องแสงครามหนึ่งเส้น ด้ามสีน้ำตาล ไม่มีโลโก้หรือสัญลักษณ์จากผลงานอื่น ต้องมองจากกล้องบุคคลที่สามแล้วจำได้ มีจุดจับและตำแหน่ง trail ชัด ส่งภาพร่างก่อนทำโมเดลเกม”

ไม่ใช้คำสั่ง “ทำเหมือนอาวุธตัวละคร X” เป็น art bible แยก prompt, ผลลัพธ์, การปรับ และข้อมูลสิทธิ์ไว้ตาม asset ID

## 9. เสียงและเอฟเฟกต์

เสียงชาร์จต้องไต่ระดับและหยุดทันทีเมื่อยกเลิก เสียงมอนเตือนสำคัญกว่าดนตรี เสียงเมืองเว้นช่อง ไม่เล่นเพลงหลายวงพร้อมกันทุกหน้าร้าน ท่าของผู้เล่นอื่นลดระดับเสียงและความหนาแน่นเมื่อไกล

VFX ใช้ pool และมีอายุสูงสุด ทุกชิ้นถูกล้างเมื่อ encounter จบ สลับฉาก หรือตัวละครหาย จำกัดความสว่างและ screen shake ไม่มีแฟลชบังคับทั้งจอ โหมดลดเอฟเฟกต์ยังเห็นระยะโจมตีและข้อมูลที่ใช้ตัดสินใจ

## 10. เกณฑ์ asset ready

ID/เวอร์ชัน/สิทธิ์ครบ, scale/pivot ถูก, collision ผ่าน, ไม่มี script แปลกปลอมจาก asset ภายนอก, animation และเสียงใช้งานใน ownership ของเกมได้, LOD/โหมดประหยัดผ่าน, มองเห็นบนมือถือ, และมีภาพรับงานใน Studio

การผ่านต้องมีผู้ตรวจและหลักฐาน ไม่เปลี่ยนสถานะ approved เพียงเพราะ generator แจ้งงานเสร็จ ไม่แทรก asset ที่มี script ไม่รู้ที่มาเข้าฉาก production
