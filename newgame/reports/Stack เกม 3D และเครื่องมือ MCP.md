# อยู่บนเว็บต่อ แล้วเปลี่ยนวิธีสร้างภาพ

คำตอบสั้นที่สุดคือ **ไม่ต้องย้ายไป Unreal และไม่ต้องเปลี่ยนเอนจิน ให้ใช้ three.js + Vite + TypeScript ต่อ (อัปเดตจาก 0.170 เป็นรุ่นล่าสุด 0.186)** แล้วเปลี่ยนที่มาของตัวละคร ท่าทาง และเอฟเฟกต์ เกมตอนนี้ "ปล่อยไม่ได้" เพราะตึกเป็นกล่องเปล่า ตัวละครต่อจากโค้ด และท่าทางคีย์ด้วยมือ ไม่ใช่เพราะ three.js ทำไม่ได้ ทางที่เหมาะคือเสียเงินเดือนเดียวให้ **Tripo หรือ Meshy (แผนเสียเงิน ประมาณ 20 ดอลลาร์ต่อเดือน)** เพื่อให้ Claude สั่งปั้นโมเดล ใส่กระดูก และใส่ท่าผ่าน API ได้เอง จากนั้นใช้ **คลังท่าฟรี Quaternius UAL2 (CC0)** สำหรับท่าต่อสู้ ใช้ **PixelLab ที่ต่อไว้แล้ว** ทำเอฟเฟกต์และ UI แบบ pixel และใช้ **ElevenLabs** ทำเสียง ค่าใช้จ่ายรวมช่วงเริ่มราว **20–60 ดอลลาร์ต่อเดือน เป็นเวลา 1–2 เดือน** สิ่งที่ผู้สร้างต้องทำเองมีไม่กี่อย่าง คือสมัครบริการ เปิดให้เครื่องคลาวด์ของ Claude ออกเน็ตไปหาบริการนั้น ใส่รหัส API เป็นความลับของ environment และเล่นทดสอบบนมือถือ ข้อควรรู้คือเครื่องมือ MCP ของ Unreal, Unity, Godot และ Blender ทั้งหมด **ต้องเปิดโปรแกรมบนคอมของผู้สร้างค้างไว้** จึงใช้จากคลาวด์ไม่ได้ ส่วนข้อมูลราคาจำนวนมากมาจากสรุปผลค้นหา เพราะเว็บผู้ขายหลายเจ้าเปิดจากเครื่องคลาวด์ไม่ได้ ต้องเช็กราคาจริงก่อนจ่าย

## ปัญหาอยู่ที่ภาพ ไม่ใช่เอนจิน จึงไม่ควรย้ายไป Unreal

เงื่อนไขของงานนี้แปลก ๆ อยู่สามข้อ Claude ทำงานในเครื่องคลาวด์ที่ **ไม่มีการ์ดจอและไม่มีหน้าจอ** ผู้สร้างเขียนโปรแกรมไม่เป็น และผู้เล่นเล่นผ่านลิงก์เว็บบนมือถือ เอนจินที่ผ่านทั้งสามข้อมีแค่กลุ่ม JavaScript (three.js, Babylon.js, PlayCanvas แบบไม่ใช้ Editor) เพราะ Claude สร้าง รัน ทดสอบ และถ่ายภาพหน้าจอได้เองในเครื่องคลาวด์ ไฟล์ทุกไฟล์เป็นข้อความ และ build ออกมาเป็นเว็บที่ส่งลิงก์ได้ทันที นี่คือวิธีเดียวกับที่เทสต์ Playwright ของเกมทำงานอยู่ตอนนี้ ในเครื่องคลาวด์นี้ **ไม่มี Blender และไม่มี Godot ติดตั้งอยู่** (ตรวจในเครื่องเมื่อ 20 ต.ค. 2569)

Unreal ไม่เหมาะกับงานนี้ด้วยเหตุผลง่าย ๆ ไฟล์ฉากเป็นไฟล์ไบนารีที่ Claude อ่านไม่ได้ โปรแกรมใหญ่หลายสิบ GB ต้องเปิดบน Windows และ **ไม่มีทางส่งออกเป็นเกมเว็บ** ปลั๊กอิน MCP ของ Unreal 5.8 ยังเป็นรุ่นทดลอง และทำงานเป็นเซิร์ฟเวอร์ในเครื่องที่เปิดโปรแกรมอยู่ ([gamedev.net](https://gamedev.net/news/4002/)) ตัวที่ชุมชนทำ (unreal-mcp) เขียนชัดว่า "EXPERIMENTAL" ไม่ควรใช้จริง และต้องใช้ Visual Studio ([GitHub unreal-mcp](https://github.com/chongdashu/unreal-mcp)) Unreal 6 ที่ประกาศว่าจะทำงานกับ Claude ผ่าน MCP ยังเป็นแค่แผน early access ปลายปี 2570 ([Startup Fortune](https://startupfortune.com/epic-games-is-handing-unreal-engine-6-the-keys-to-generative-ai-and-the-model-that-wins-the-default-slot-wins-the-industry/))

หลักฐานจากเกมที่ AI เขียนแล้วมีคนเล่นจริงก็ชี้ทางเดียวกัน เกมบิน fly.pieter.com ของ Pieter Levels ทำด้วย Cursor + Claude + three.js ในราว 3 ชั่วโมง และมีผู้เล่นหลักหมื่นคน ([Indie Hackers](https://www.indiehackers.com/post/2NUIOp80SUWuPmmfKoS9)) งาน Cursor Vibe Jam 2026 ที่บังคับให้โค้ด 90% มาจาก AI แนะนำ three.js มีเกมส่ง 945 เกม ([Colyseus](https://colyseus.io/blog/vibe-jam-2026/)) แต่ต้องพูดตรง ๆ ว่าเกมเหล่านี้ **เป็นเกมเล็ก กลไกเดียว ภาพเรียบง่าย** ความสำเร็จของ Levels มาจากผู้ติดตามที่สะสมมาสิบปีด้วย ([404 Media](https://404media.co/this-game-created-by-ai-vibe-coding-makes-50-000-a-month-yours-probably-wont)) งานวิจัยนี้ **ไม่พบเกม action RPG 3D บนแผนที่เมืองจริงที่ AI สร้างเกือบทั้งหมดแล้วออกขายได้ดี** เลย งานของเราจึงเป็นงานบุกเบิก ข้อเสียเปรียบจริงคือปริมาณงานภาพและความเนียน ไม่ใช่ความสามารถเขียนโค้ด

**ทางเลือกรอง: ย้ายไป Babylon.js 9** น่าสนใจเพราะมีของในตัวมากกว่า Claude ต้องต่อไลบรารีเองน้อยลง และเปลี่ยนแค่ชั้นวาดภาพใน `apps/citywalk` เพราะ `packages/rpg-core` ไม่ผูกกับเอนจิน แต่ระบบย้ายท่าของ Babylon ยังใหม่และเพิ่งแก้บั๊ก ต้องใช้รุ่น 9.7 ขึ้นไป ([Babylon forum](https://forum.babylonjs.com/t/after-anim-retarget-stopping-current-animation-jumps-to-rest-pose/63379)) ข้อแนะนำคือยังไม่ย้าย จนกว่าจะเจอปัญหาที่ three.js แก้ไม่ได้จริง

## ตัวละครและท่าทาง: เสียเงินเดือนเดียวให้ Tripo หรือ Meshy คู่กับคลังท่าฟรี

ในบรรดาเครื่องมือปั้นโมเดลด้วย AI มีแค่ **Meshy กับ Tripo** ที่ทำครบทั้ง "ปั้น → ใส่กระดูก → ใส่ท่า" ผ่าน API และมีเครื่องมือสำหรับ AI agent อย่างเป็นทางการ ผลลัพธ์เป็น GLB ชื่อกระดูกแบบ Mixamo ซึ่งต่อเข้า rig ของเกมผ่าน `joints`/`restFix` ใน `assets.json` ได้อยู่แล้ว

**Meshy** มี MCP ทางการ `@meshy-ai/meshy-mcp-server` รุ่น 0.6.4 (13 ต.ค. 2569) มี 28 เครื่องมือ รวมปั้นจากข้อความ ปั้นจากภาพ ใส่กระดูก ใส่ท่า และสร้างท่าจากข้อความ แต่ **รหัส API ต้องใช้แผน Pro ขึ้นไป** ([npm Meshy MCP](https://registry.npmjs.org/@meshy-ai/meshy-mcp-server)) โหมด Smart Topology (meshy-t2) ปั้นโมเดลแบบประหยัดรูปทรงได้ตรงจำนวนหน้าที่ต้องการ ค่าเริ่ม 4,000 หน้า เหมาะกับมือถือ แผนฟรีให้ 100 เครดิตต่อเดือน และ **ผลงานจากแผนฟรีเป็น CC BY 4.0** คือใครก็เอาไปใช้ได้ถ้าให้เครดิต ส่วน Pro ราคา 20 ดอลลาร์ต่อเดือน ได้ 1,000 เครดิต และเก็บผลงานเป็นส่วนตัวได้ ([Meshy pricing](https://meshy.ai/pricing)) มีรายงานว่าแผนฟรีอาจดาวน์โหลดไม่ได้เลย แหล่งนี้เป็นคู่แข่งจึงเชื่อได้น้อย ([Ludo](https://ludo.ai/compare/meshy-alternatives)) แต่ตรงกับที่ผู้สร้างเจอ ผลที่ผู้สร้างลองจาก Meshy ฟรี จึง **ไม่ใช่ตัวแทนของสิ่งที่ทำได้จริง** เพราะไม่ได้ใช้โหมดลดหน้า ไม่ได้ผ่านขั้นจัดกระดูกให้ตรง rig และไม่ได้ผ่านภาพแบบ pixel 3D ของเกม

**Tripo** ไม่มี MCP ที่ใช้ได้ดี (ตัวทางการเป็นรุ่น alpha ที่ต้องมี Blender) ([GitHub tripo-mcp](https://github.com/VAST-AI-Research/tripo-mcp)) แต่มี **`tripo-cli` ทางการ รุ่น 0.7.2 ที่ออกแบบมาให้ agent ใช้โดยตรง** มีโหมด `--for game-mobile` สั่งต่อกันได้ในบรรทัดเดียว (ปั้น → ลงสี → ใส่กระดูก → แปลงไฟล์) และแสดงค่าใช้จ่ายก่อนจ่ายจริง ([npm tripo-cli](https://registry.npmjs.org/tripo-cli)) ใส่กระดูก 25 เครดิต (0.25 ดอลลาร์) ใส่ท่า 0.10 ดอลลาร์ต่อท่า มีท่าสำเร็จรูป 100 กว่าท่า ([Tripo pricing](https://developers.tripo3d.ai/en/pricing)) แผน Professional 19.90 ดอลลาร์ต่อเดือน 3,000 เครดิต ([MakerStack](https://makerstack.co/reviews/tripo-3d-review/)) ข้อควรระวังคือ API รุ่น V2 ทั้งหมดจะหยุด 1 พ.ย. 2569 ต้องใช้ v3 เท่านั้น ([Tripo docs](https://docs.tripo3d.ai/get-started/pricing.html))

ยังไม่มีใครทดสอบสองเจ้านี้กับตัวละครแบบเกมของเราตัวต่อตัว คำแนะนำคือ **เอาภาพคอนเซปต์ตัวเดียวกัน ท่า A-pose หันหน้าตรง ส่งเข้าทั้งสองเจ้า** (ใช้เงินไม่กี่ดอลลาร์) แล้วตรวจด้วย `check-model` และให้ผู้สร้างดูภาพในเกมจริงก่อนเลือก ท่อเหล็กควรเป็นไฟล์ GLB แยก เสียบที่มือขวา ไม่ปั้นติดตัว เพราะไม่มีแหล่งไหนบอกว่าระบบใส่กระดูกอัตโนมัติจัดการของในมือได้ดี

ทางที่ **ไม่ต้องเสียเงินเลย** ก็มี คือใช้ตัวละครฟรีที่ใส่กระดูกแล้วจากศิลปินชุดเดียวกัน เช่น KayKit (CC0, glTF) หรือ Quaternius ([Cinevva guide](https://app.cinevva.com/guides/free-rigged-3d-character-models)) แล้วต่อเข้า rig ของเกม ข้อดีคือสไตล์ตรงกันทั้งชุด ข้อเสียคือหน้าตาไม่ใช่ของเราเอง และใบอนุญาตสรุปมาจากเว็บบุคคลที่สาม ต้องเช็กหน้าต้นฉบับ

เรื่องท่าทาง แหล่งที่ตรงกับเกมที่สุดคือ **Quaternius Universal Animation Library 2** (ม.ค. 2569, CC0) มี 130 กว่าท่าบนโครงกระดูกเดียว มี **คอมโบอาวุธ 3 และ 4 จังหวะที่แยกเป็นจังหวะตีและจังหวะคืนท่า** ตรงกับคอมโบตีท่อเหล็ก 3 จังหวะที่มีอยู่ รุ่นฟรีมีราว 70% ของทั้งหมด ([Digital Production](https://digitalproduction.com/2026/02/10/130-animations-one-rig-zero-drama/); [itch.io](https://quaternius.itch.io/universal-animation-library-2)) Mixamo ยังฟรีและใช้ในเกมขายได้ แต่ไม่มี API และไม่มีคนดูแลแล้ว ([AssetForgeIndex](https://assetforgeindex.com/tools/mixamo)) การย้ายท่าจาก Mixamo ไปโครงอื่นใน three.js มีปัญหาบ่อย เช่น ตัวหมุน แขนกลับด้าน ([three.js forum](https://discourse.threejs.org/t/fixing-skeletonutils-retarget-and-retargetclip-functions/65149/2)) จึงควร **แปลงท่าล่วงหน้าครั้งเดียว ให้ตรงชื่อกระดูกใน `rig.json`** ไม่ใช่แปลงตอนเกมรัน งานนี้ Claude ทำในเครื่องคลาวด์ได้ด้วย Blender แบบไม่มีหน้าจอ (แพ็กเกจ `bpy` 5.2.2 ติดตั้งผ่าน pip ได้ ([PyPI bpy](https://pypi.org/pypi/bpy/json))) แต่ **ยังไม่ได้ลองติดตั้งจริงในเครื่องนี้**

มีเรื่องหนึ่งที่ผู้สร้างต้องตัดสินใจ กติกาปัจจุบันบอกว่า "ท่าทางตัวละครเขียนในโค้ด (`src/hero.ts`)" ถ้าจะเอาท่าจากคลังมาใช้ มีสองทาง ทางแรกคือแปลงท่าจากคลังเป็นข้อมูลใน `src/anim/clips.ts` ซึ่งยังตรงกติกาเดิม ทางที่สองคือฝังท่าไว้ในไฟล์ GLB เลย ซึ่งง่ายกว่าแต่ต้องเปลี่ยนกติกา ข้อแนะนำคือ **ทางแรก** เพราะยังปรับจังหวะตีและหยุดภาพตอนโดนได้จาก config เหมือนเดิม

มอนสไลม์ไม่ต้องใช้ AI ปั้น เพราะเกมวาดสไลม์ด้วยโค้ดอยู่แล้ว เครื่องมือ AI จะใช้กับมอนแบบอื่นในภายหลัง

## เมือง เอฟเฟกต์ เสียง และ UI: ส่วนใหญ่ทำด้วยโค้ดและของฟรีได้

**แผนที่เมือง** ทางที่ดูสวยทันทีคือ Google Photorealistic 3D Tiles ซึ่งต่อกับ three.js ได้ผ่าน `3d-tiles-renderer` ([unpkg 3d-tiles-renderer](https://unpkg.com/3d-tiles-renderer@0.5.0/src/core/plugins/API.md)) แต่ **ไม่แนะนำ** ด้วยสี่เหตุผล ข้อแรก Google ห้ามเก็บไว้ในเครื่องหรือเล่นออฟไลน์ และต้องแสดงโลโก้ Google ([Map Tiles API Policies](https://developers.google.com/maps/documentation/tile/policies)) ข้อสอง เกินโควตาฟรี 1,000 ครั้งต่อเดือนแล้วคิด 6 ดอลลาร์ต่อ 1,000 ครั้ง ([Google pricing](https://developers.google.com/maps/billing-and-pricing/pricing)) ข้อสาม ตึกทั้งเมืองเป็นผิวก้อนเดียว ไม่แยกเป็นหลัง ทำให้ชนตึกหรือหาทางเดินยาก ข้อสี่ ภาพถ่ายจริงพอแปลงเป็น pixel จะดูเละ และขัดกับภาพ pixel 3D ที่ผู้สร้างเลือกไว้ ยังไม่ได้ยืนยันด้วยว่าเชียงใหม่มีข้อมูลนี้หรือไม่ ทางที่แนะนำคือ **ใช้ OSM ต่อ แต่ให้ Claude เขียนโค้ดสร้างตึกที่ดีขึ้น** ใส่ทรงหลังคาจากข้อมูล `roof:shape` ใส่ภาพหน้าตึกแบบตึกแถว บ้านไม้ คอนโด ใส่หน้าต่างและหน้าร้านชั้นล่าง และเพิ่มของประดับถนนกับต้นไม้ แล้วปั้นพื้นที่หลักบางจุดให้ละเอียดเป็นพิเศษ เช่น ลานประตูท่าแพ ส่วนอื่นของเมืองใช้แบบสร้างอัตโนมัติ เครื่องมือ OSM2World ส่งออกเป็น glTF พร้อมลายผิวได้และรันแบบคำสั่งได้ ([OSM wiki](https://wiki.openstreetmap.org/wiki/OSM2World)) ต้องใส่ข้อความ "© OpenStreetMap contributors" เสมอ และวัดยังห้ามเป็นสนามต่อสู้ตามกติกาเดิม

**ลายผิวและท้องฟ้า** ภาพ pixel 3D ย่อภาพลงมาก รายละเอียดผิววัสดุแบบเต็มจะหายไปเกือบหมด จึงพอแล้วกับ **ภาพสีพื้นแบบต่อกันได้หนึ่งชุด** สำหรับพื้น ผนัง หลังคา และหน้าตึก แหล่งฟรีที่ Claude ดึงได้คือ ambientCG (CC0 มี API v3 ไม่ต้องใช้รหัส) ([ambientCG docs](https://docs.ambientcg.com/api/v3/)) ส่วน Poly Haven ไฟล์เป็น CC0 แต่ **API ฟรีเฉพาะงานไม่แสวงกำไร** จึงควรดาวน์โหลดทีละไฟล์แทน ([Poly Haven API](https://polyhaven.com/our-api)) PixelLab ที่ต่อไว้แล้วก็มี `create_building_kit` และ `create_tiles_pro` สำหรับชิ้นส่วนตึกแบบ pixel ท้องฟ้าวาดไล่สีด้วยโค้ดน่าจะเข้ากับภาพ pixel ที่สุด ถ้าอยากได้ภาพดอยสุเทพเป็นฉากหลัง Blockade Labs มี API เริ่มราว 20 ดอลลาร์ต่อเดือน แต่หน้าราคายังขัดกันอยู่ ([Blockade API](https://api.blockadelabs.com))

**เอฟเฟกต์ (VFX)** ทำได้สามชั้น ชั้นแรก Claude เขียนเองด้วยโค้ด เช่น เส้นแสงตามท่อเหล็กตอนเหวี่ยง ซึ่งใช้วิธีเก็บตำแหน่งปลายอาวุธทุกเฟรมแล้วสร้างแถบที่จางลง ([80.lv](https://80.lv/articles/slow-motion-sword-trail-effect-recreated-with-three-js)) ชั้นที่สองใช้ไลบรารี **three.quarks** ซึ่งมีอนุภาค เส้นตาม และภาพเคลื่อนไหวจากแผ่นภาพ แต่ **รุ่น 0.17 ต้องใช้ three 0.182 ขึ้นไป** ถ้ายังไม่อัปเดต three ต้องใช้รุ่น 0.16.0 ([npm three.quarks](https://www.npmjs.com/package/three.quarks)) ชั้นที่สามใช้ **PixelLab `vfx_workbench`** ที่มีอยู่แล้ว ทำเอฟเฟกต์ pixel เช่น ระเบิด ออร่า แสงตอนโดนตี แล้วส่งออกเป็นแผ่นภาพ PNG + JSON ฟรีสำหรับสมาชิก ([PixelLab ToS](https://pixellab.ai/termsofservice)) ตอนวิจัยลองเรียกเครื่องมือนี้จากตัวช่วยย่อยแล้วได้ error 401 จึง **ยังไม่ได้เห็นผลจริง** ควรลองใหม่ในหน้าต่างหลัก EmberGen ซึ่งเป็นโปรแกรมทำเอฟเฟกต์ไฟ/ควันชั้นนำต้องใช้การ์ดจอบนคอม จึงใช้จากคลาวด์ไม่ได้

**เสียง** เกมมีระบบสังเคราะห์เสียงด้วยโค้ดและตัววัดเสียงอยู่แล้ว (`src/audio/`) ใช้ต่อกับเสียงปุ่มและเสียงตี ส่วนเสียงธรรมชาติ เช่น ไฟ น้ำ เสียงตลาด เสียงตุ๊กตุ๊ก ใช้ **ElevenLabs** ซึ่งสร้างเสียงสั้นได้ถึง 30 วินาทีและวนลูปได้ ([ElevenLabs SFX docs](https://elevenlabs.io/docs/overview/capabilities/sound-effects)) ElevenLabs มี **MCP แบบออนไลน์ทางการ** ที่ `https://api.elevenlabs.io/v1/mcp` (เข้าระบบแบบ OAuth) แทนตัวเดิมที่เลิกดูแลแล้ว ([GitHub elevenlabs-mcp](https://github.com/elevenlabs/elevenlabs-mcp)) แผนฟรีใช้เพลงเชิงพาณิชย์ไม่ได้ ต้องเริ่มที่ Starter 6 ดอลลาร์ต่อเดือน ([licenseorg](https://licenseorg.com/blog/ai-music-licensing-suno-elevenlabs)) แต่สิทธิ์เพลงสำหรับเกมยังมีข้อมูลขัดกัน ต้องอ่านเงื่อนไขก่อนใช้ Suno ไม่แนะนำ เพราะหลังดีลกับ Warner ผู้ใช้ไม่ได้เป็นเจ้าของเพลงเต็มที่ ([Music in Africa](https://www.musicinafrica.net/magazine/suno-adjusts-ai-music-ownership-terms-after-warner-music-partnership)) ของฟรีสำรองคือ Kenney (CC0) Claude ฟังเสียงไม่ได้ แต่ใช้ตัววัดเสียงที่มีอยู่ตรวจความดังและเสียงแตกได้

**UI และไอคอน** ใช้ PixelLab (`create_ui_asset`, `pixelart_workbench`) หรือให้ Claude วาดเป็นตัวอักษรใน `ui/pixelIcons.ts` ตามกติกาเดิม ภาพอ้างอิงหรือภาพบรรยากาศใช้ Google Imagen 4 Fast ราว 0.02 ดอลลาร์ต่อภาพ ([pricepertoken](https://pricepertoken.com/imagen-pricing)) แล้วแปลงเป็น pixel ผ่าน PixelLab

ถ้าอยากได้ประตูเดียวที่เข้าถึงโมเดลสร้างภาพ เสียง และ 3D หลายร้อยตัว **fal.ai มี MCP ออนไลน์ทางการ** ([fal MCP docs](https://fal.ai/docs/model-apis/mcp)) Scenario ก็มี MCP ออนไลน์ เริ่ม 15 ดอลลาร์ต่อเดือน ([Scenario help](https://help.scenario.com/articles/2664328768-getting-started-with-the-scenario-mcp-server)) ทั้งคู่เป็นทางเลือก ไม่จำเป็นในช่วงแรก และใบอนุญาตต่างกันไปตามแต่ละโมเดล

## เครื่องมือแบบ MCP ส่วนใหญ่ต้องใช้คอมของผู้สร้าง

ข้อนี้สำคัญกับคำถามว่า "Claude ส่งงานออกไปได้ไหม" MCP มีสองแบบ แบบออนไลน์ (Claude ต่อผ่าน URL ได้จากทุกที่) และแบบในเครื่อง (ต้องรันโปรแกรมบนเครื่องเดียวกัน) **MCP ของ Blender, Unity, Unreal, Godot และ PlayCanvas เป็นแบบในเครื่องทั้งหมด** และต้องเปิดโปรแกรมหลักค้างไว้ ตัวอย่างเช่น Blender MCP ที่ดังที่สุด (ดาวราว 31,800) รันเซิร์ฟเวอร์ในโปรแกรม Blender ที่เปิดอยู่ ([GitHub blender-mcp](https://github.com/ahujasid/blender-mcp)) Claude Code ในคลาวด์จึงใช้ไม่ได้

| เครื่องมือ | Claude ในคลาวด์เรียกได้ไหม | วิธีต่อ |
|---|---|---|
| PixelLab | ได้ ต่อแล้ว | MCP ออนไลน์ |
| ElevenLabs | ได้ ถ้าต่อ connector | MCP ออนไลน์ (OAuth) |
| fal.ai, Scenario | ได้ ถ้าต่อ connector | MCP ออนไลน์ |
| Meshy | ได้ ถ้าเปิดเน็ตและใส่รหัส | MCP รันด้วย npx ในเครื่องคลาวด์ หรือเรียก REST ([npm Meshy MCP](https://registry.npmjs.org/@meshy-ai/meshy-mcp-server)) |
| Tripo | ได้ ถ้าเปิดเน็ตและใส่รหัส | `tripo-cli` หรือ SDK |
| Blender (แบบไม่มีหน้าจอ) | น่าจะได้ ยังไม่ได้ลอง | สคริปต์ `bpy` ไม่ใช้ MCP |
| Blender MCP, Unity, Unreal, Godot | ไม่ได้ | ต้องเปิดโปรแกรมบนคอมผู้สร้าง |
| Mixamo, AccuRIG, Cascadeur | ไม่ได้ | คนต้องกดเองบนเว็บหรือโปรแกรม |

ทางอ้อมสำหรับคนที่มีคอมแรง ๆ คือ Claude Code **Remote Control** ซึ่งให้ session รันบนคอมของผู้สร้าง ใช้ MCP ในเครื่องได้ และสั่งงานจากมือถือได้ ([Claude Code Docs](https://code.claude.com/docs/en/remote-control)) แต่ต้องเปิดคอมไม่ให้หลับ ต้องติดตั้ง Blender และถ้าเน็ตหลุดราว 10 นาทีก็ต้องเริ่มใหม่ ([cloudroom.dev](https://www.cloudroom.dev/blog/claude-code-remote-control)) **ไม่แนะนำสำหรับช่วงนี้** เพราะเพิ่มขั้นตอนเปราะบางให้ผู้สร้าง

ข้อสังเกตจากเครื่องคลาวด์นี้ (ตรวจเมื่อ 20 ต.ค. 2569) เครือข่ายของ session **ปิดกั้นเว็บผู้ขายเกือบทั้งหมด** เช่น elevenlabs.io, polyhaven.com, ambientcg.com และเว็บเอกสารของ Meshy กับ Tripo ใช้ได้แค่ npm, PyPI และบริการของ Anthropic ก่อนเริ่มใช้เครื่องมือใด ผู้สร้างจึงต้องเพิ่มชื่อเว็บนั้นในรายการที่อนุญาตของ environment ก่อน

## ค่าใช้จ่ายจริงราว 20–60 ดอลลาร์ต่อเดือน ในช่วง 1–2 เดือนแรก

งานขนาดตัวเอก 1 ตัว มอน 10 แบบ และท่า 30 ท่า ถ้าคิดตามราคา API จะใช้ราว 600–1,250 เครดิต Meshy (สมมติว่าลองใหม่ 3 ครั้งต่อโมเดล ตัวเลขนี้เป็นการเดา ไม่มีแหล่งไหนวัดไว้) เท่ากับ Pro 1–2 เดือน ([npm Meshy MCP](https://registry.npmjs.org/@meshy-ai/meshy-mcp-server)) ถ้าใช้ Tripo ค่าใส่ท่า 30 ท่าเหลือราว 3 ดอลลาร์ บวกค่าปั้นที่ยังหาราคาต่อชิ้นไม่ได้ ต้นทุนจริงคือเวลาเก็บงาน ได้แก่ ตรวจรูปทรง ตรวจด้วย `check-model` จัดจุดเสียบอาวุธ และแปลงท่าเป็นโค้ด

| รายการ | ทางฟรี | ทางแนะนำ | หมายเหตุ |
|---|---|---|---|
| ตัวละคร + กระดูก | KayKit / Quaternius (0) | Tripo Professional 19.90 หรือ Meshy Pro 20 ดอลลาร์/เดือน | เลือกเจ้าเดียว เลิกได้หลังงานเสร็จ |
| ท่าทาง | Quaternius UAL2, Mixamo (0) | เหมือนทางฟรี + ท่าจาก Tripo/Meshy บางท่า | |
| ภาพ UI / เอฟเฟกต์ pixel | PixelLab (สมาชิกอยู่แล้ว) | PixelLab | ต้องเช็กเครดิตก่อนทำชุดใหญ่ตามกติกาเดิม |
| ลายผิวตึก | ambientCG (0) | + Imagen ราว 0.02 ดอลลาร์/ภาพ | |
| เสียง | โค้ดสังเคราะห์ + Kenney (0) | ElevenLabs Starter 6 ดอลลาร์/เดือนขึ้นไป | ราคาเครดิตเสียงยังขัดกัน |
| ท้องฟ้า | วาดด้วยโค้ด (0) | Blockade ราว 20 ดอลลาร์ 1 เดือน (ถ้าต้องการ) | |

ของที่ **ไม่คุ้มในตอนนี้** ได้แก่ Hyper3D Rodin ซึ่ง API ต้องใช้แผน Business 96–120 ดอลลาร์ต่อเดือนและไม่มีระบบใส่กระดูก ([hyper3d.ai pricing](https://hyper3d.ai/pricing)) Hunyuan3D ที่ต้องใช้การ์ดจอและใบอนุญาตห้ามใช้ใน EU, UK และเกาหลีใต้ ([Hunyuan3D LICENSE](https://huggingface.co/tencent/Hunyuan3D-2/blob/main/LICENSE)) และ Unity Pro ที่ราคา 2,310 ดอลลาร์ต่อที่นั่งต่อปี ([Unity pricing](https://unity.com/products/pricing-updates))

## สิ่งที่ผู้สร้างต้องตั้งค่าเอง และลำดับงานที่แนะนำ

Claude ทำงานแทนได้เกือบทั้งหมด แต่บางอย่างเป็นเรื่องบัญชี เงิน และสิทธิ์ ซึ่งต้องเป็นผู้สร้างเท่านั้น

| ผู้สร้างต้องทำ | ทำเมื่อไร | ทำไม |
|---|---|---|
| เลือกและสมัคร Tripo หรือ Meshy แผนเสียเงิน 1 เดือน | หลัง Claude เสนอผลทดลองเทียบ | สมัครและจ่ายเงินต้องให้ผู้สร้างตัดสิน |
| เพิ่มชื่อเว็บ API ในรายการที่อนุญาตของ environment เช่น `api.meshy.ai` หรือ `openapi.tripo3d.ai` | ก่อนเริ่มปั้นโมเดล | ตอนนี้เครือข่ายปิดกั้นอยู่ |
| ใส่รหัส API เป็น secret ของ environment เช่น `MESHY_API_KEY` หรือ `TRIPO_API_KEY` | พร้อมข้อบน | ห้ามเก็บรหัสในโค้ด |
| ต่อ connector ของ ElevenLabs ใน claude.ai (ถ้าจะใช้) | ช่วงทำเสียง | เป็น MCP ออนไลน์ เข้าระบบแบบ OAuth ยังไม่ได้ยืนยันว่ามีในรายการ connector |
| ตรวจว่า PixelLab ใช้ได้ในหน้าต่างหลัก | ก่อนทำเอฟเฟกต์ | ตัวช่วยย่อยเรียกแล้วได้ error 401 |
| อนุมัติหน้า "กติกาสไตล์" และภาพเปรียบเทียบก่อน/หลัง | ทุกขั้น | Claude เห็นแค่ภาพนิ่ง ตัดสินความสนุกไม่ได้ |
| เล่นบนมือถือจริงหลังจบแต่ละขั้น | ทุกขั้น | บั๊กที่ร้ายที่สุดเจอได้จากการเล่นเท่านั้น ([cinevva guide](https://app.cinevva.com/guides/vibe-coding-games)) |

ลำดับงานด้านล่างเริ่มจากของฟรีก่อน แล้วค่อยจ่ายเงินเมื่อรู้แล้วว่าต้องการอะไร

| ขั้น | งาน | ใครทำ | เสียเงินไหม |
|---|---|---|---|

ขั้น 3 สำคัญที่สุด เพราะตอบได้เร็วและฟรีว่า "ภาพดีขึ้นจนปล่อยได้ไหม" ถ้าดีขึ้นพอ อาจไม่ต้องจ่ายค่าปั้นโมเดลเลย

## สิ่งที่งานวิจัยนี้ยังไม่รู้

ต้องบอกตรง ๆ ว่างานนี้มีช่องว่าง เว็บผู้ขายส่วนใหญ่เปิดจากเครื่องคลาวด์ไม่ได้ ราคาหลายตัวจึงมาจากสรุปผลค้นหาหรือเว็บบุคคลที่สาม และบางตัวขัดกัน (เช่น ราคาแผนรายปีของ Meshy ราคา Blockade และราคาเสียงของ ElevenLabs) ยังไม่รู้ว่ารหัส API ของ Meshy Pro ใช้เครดิตรายเดือนหรือต้องซื้อเครดิต API แยก ([meshyiai.com](https://meshyiai.com/pricing/)) ยังหาราคาปั้นต่อชิ้นของ Tripo P1/P2 ไม่ได้ ยังไม่ได้อ่านเงื่อนไขทางการว่าถ้าเลิกสมาชิกแล้วยังเป็นเจ้าของโมเดลอยู่หรือไม่ ยังไม่ได้ลองติดตั้ง Blender ในเครื่องคลาวด์ ยังไม่รู้ว่าเชียงใหม่มีข้อมูล Google 3D หรือไม่ และไม่มีตัวเลขเปรียบเทียบความเร็ว three.js กับ Babylon.js บนมือถือราคากลาง ตัวเลข "ลองใหม่ 3 ครั้งต่อโมเดล" เป็นการเดา และยังไม่มีใครทดสอบตัวละครแบบเกมเราด้วย Meshy กับ Tripo ทุกตัวเลขในรายงานนี้จึงควรถือเป็นค่าประมาณ และต้องเช็กหน้าราคาจริงก่อนจ่าย

## สรุป

คำถามจริงไม่ใช่ "เอนจินไหนเก่งที่สุด" แต่เป็น "ส่วนไหนของงานที่ Claude ทำเองได้จากคลาวด์" คำตอบแบ่งงานออกเป็นสองฝั่งชัดเจน ฝั่งโค้ด เมือง เอฟเฟกต์ เสียงสังเคราะห์ และการทดสอบ Claude ทำได้ครบบนเว็บอยู่แล้ว ส่วนฝั่งปั้นโมเดล ใส่กระดูก และท่าทาง ต้องใช้บริการภายนอกที่มี API คือ Tripo หรือ Meshy การย้ายไป Unreal จะทำให้ฝั่งแรกพังทั้งหมด และไม่ได้แก้ฝั่งที่สองเลย

บทเรียนจากเกมที่ AI สร้างแล้วสำเร็จคือ **ภาพที่ไปทางเดียวกันทั้งเกมสำคัญกว่าภาพที่ละเอียด** ภาพ pixel 3D ที่ผู้สร้างเลือกไว้จึงเป็นข้อได้เปรียบ เพราะช่วยกลบความไม่เท่ากันของโมเดลจากหลายแหล่ง ก้าวถัดไปที่คุ้มที่สุดคือขั้น 3 (ตัวละครและท่าฟรีบนกติกาสไตล์เดียว) แล้วให้ผู้สร้างเล่นบนมือถือก่อนตัดสินใจจ่ายเงินใด ๆ
